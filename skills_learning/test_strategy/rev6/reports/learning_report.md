## 知识模式

### 领域专有 (10个)
- [95%] Test strategy: 定义测试范围、目标与资源分配的高层计划
- [90%] Test plan: 详细描述测试活动、时间表与交付物的文档
- [90%] 测试策略应作为软件开发周期的测试方法大纲，提供合理且系统的测试方向指导。
- [90%] 测试策略应记录在测试计划中，详细描述验证和确认产品系统的具体方法。
- [85%] Test construction strategies: 设计测试用例的方法，如等价类划分与边界值分析
- [85%] 测试策略需明确设计中的可测试方面及其测试参数，确保测试覆盖关键功能。
- [85%] 测试策略应与测试计划、测试环境创建等测试规划活动紧密结合，形成完整的工作流。
- [80%] 测试策略需考虑测试对象、测试基础设施、人员技能和质量目标等多因素，以全面分析测试工作量。
- [75%] A/B testing: 对比两个版本以评估效果差异的实验方法
- [70%] Acceptance test-driven development: 通过验收测试驱动开发流程的实践

### 高级模式 (3个)
- [75%] 在验收测试驱动开发中，测试策略应包含面向客户/用户的测试，以展示系统的业务意图。
- [70%] 测试策略应避免仅依赖正向测试，需结合其他效应防止确认偏差，确保测试的全面性。
- [60%] 测试策略的构建可借鉴心理测量中的项目构建方法，以系统化方式决定测试项的设计和选择。
