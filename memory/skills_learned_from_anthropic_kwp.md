## 一、核心认知：这些技能的本质是什么？

knowledge-work-plugins 不是一组通用工具，而是一组"领域专业知识编码"——将人类专家在特定场景下的判断力、流程、注意事项，转化为 AI 可以按步执行的**可操作指令集**。

每个 skill 的核心模式：

```
用户输入（自然语言问题/需求）
  -> Skill 解析需求（判断上下文/复杂度/数据类型）
  -> 执行预定义流程（分步操作 + 条件分支 + 错误处理）
  -> 输出结构化结果（表格/报告/建议/代码）
  -> 提供扩展选项（进一步细化/生成衍生品）
```

## 二、关键技能模式提取

### 模式 A：数据探索与分析（/explore-data + /analyze）

**适用场景：** 遇到新数据集/回答数据问题

**核心步骤：**
1. **理解数据源** — 先做 profiling（行数/列数/类型/空值率/分布/异常）再分析
2. **列分类** — 分为 Identifier / Dimension / Metric / Temporal / Text / Boolean / Structural
3. **复杂度分级** — Quick answer / Full analysis / Formal report，对应不同深度
4. **先验后述** — 先探查数据质量，再做分析结论，不自以为已知数据形状
5. **结构化输出** — 每个分析输出必须包含：方法/数据/发现/建议

**关键技巧：**
- 空值率 + 基数比（distinct/total）是快速判断列质量的核心指标
- 百分位分析（p1/p5/p95/p99）比均值更能反映数据特征

### 模式 B：研究综合（/synthesize-research）

**适用场景：** 一堆散乱的研究笔记/调研资料/用户反馈需要提炼

**核心方法——主题分析（Thematic Analysis）：**
1. **熟悉化** — 通读所有原始数据，不急于编码
2. **初始编码** — 开放编码，不预设类别
3. **主题搜寻** — 将编码归组为主题
4. **主题评审** — 检查主题内部一致性和外部区分度
5. **主题定义** — 命名 + 定义边界
6. **撰写报告** — 按优先级排列，附引用证据

**优先级矩阵：** 频率 x 影响 =（Low/Low, Low/High, High/Low, High/High）

**输出结构：**
- Research Overview（方法/样本量/时间范围）
- Key Findings（5-8条，每条含：陈述句/证据/频率/影响/置信度）
- User Segments / Personas
- Opportunity Areas（未满足需求/待改进/新能力）
- Recommendations（可操作，关联发现）
- Open Questions

**关键技巧：**
- 置信度分级：High（强证据）/ Medium（暗示性）/ Low（早期信号）
- 矛盾点需要特别标注，而非掩盖
- 使用"verbatim quotes"而非意译访谈数据

### 模式 C：科学问题选择（scientific-problem-selection）

**适用场景：** 选择研究课题/评估项目可行性/做决策

**9步工作流：**
1. **直觉泵（Intuition Pumps）** — 通过系统性提问产生创新想法（三支柱：Perturbation / Measurement / Theory-Computation，各分 Logic + Technology 两个维度）
2. **风险评估** — 识别假设，评估成功概率（X轴）+ 影响力（Y轴）
3. **优化函数** — 定义成功指标（不选错度量方式）
4. **参数策略** — 固定哪些参数/放开哪些（Fix one, float the rest）
5. **决策树** — 规划决策点和"高度舞蹈"（在不同抽象层级切换）
6. **逆境规划** — 准备危机应对（"这是一直在等的危机，别浪费它"）
7. **问题反转** — 卡住时从反面思考（换个目标 / "我有答案，问题是什么？"）
8. **综合叙事** — 把所有发现整合成连贯故事（设置/问题/方法/迭代/结论/热情）
9. **元框架** — 整体编排1-8步

**关键技巧：**
- 三根支柱 + 两个维度 = 6个象限，确保不漏任何创意方向
- "Fix one, float the rest"是参数空间的黄金法则
- 逆境不是灾难——是"一直在等的危机"

### 模式 D：任务管理（productivity/task-management）

**核心流程：**
1. 收集所有任务（从上下文/对话/记忆）
2. 分类：Urgent-Important矩阵 / 按项目/领域
3. 优先级排序
4. 时间约束检查
5. 建议执行顺序

### 模式 E：产品头脑风暴（product-management/brainstorm）

**核心流程：**
1. 定义问题空间/用户需求
2. 发散——生成多种方案，不评判
3. 收敛——按可行性/影响力/风险筛选
4. 形成建议

## 三、核心模式汇总

### Skill 文件元数据格式

```yaml
---
name: skill-name
description: 一句话描述何时使用
argument-hint: "<输入提示>"
---
```

### Skill 通用结构（从多个skill提取的最佳实践）

```
1. Usage — 命令格式和使用示例
2. Workflow — 分步操作流程（关键）
   - 每一步都是可执行的原子操作
   - 每个步骤分支处理不同情况（如：当数据源连接 vs 未连接）
   - 明确标注什么情况需要问用户，什么情况可以直接做
3. Approval gates — 什么操作需要用户确认
4. Reference — 外部参考/已知问题/反模式
```

### 错误处理模式

```
- 某个数据源失败 → 跳过并标注，不中断整个流程
- 某一数据源无数据 → 记录为0并继续，不警告
- rate limit → 跳过，记录在Sources中
- 验证模式：先查数据质量，再做分析
```

### 输出结构化

```
所有输出都有固定结构：
1. 概述（范围/方法/时间/样本量）
2. 发现（按优先级排列）
3. 建议（可操作）
4. 未尽事项（不确定性/后续）
```

## 四、对我自己的技能体系的启发

### 可内化的改进

1. **分步粒度控制** — 我的SOP可以更结构化：每一步给出具体的条件分支、错误处理、用户确认点
2. **优先级矩阵** — 在信息综合时，始终使用「频率 x 影响」矩阵来排序
3. **置信度标注** — 对每一个分析结论标注置信度（High/Medium/Low），让用户自己判断
4. **数据源失败处理** — 跳过+标注，不阻塞整个流程
5. **Verbose输出结构** — 研究综合的输出格式（Overview/Findings/Segments/Opportunities/Recommendations/OpenQuestions）值得作为通用模版
6. **列分类法** — Identifier/Dimension/Metric/Temporal/Text/Boolean 分类可以作为快速理解数据结构的标准
7. **Fix one, float the rest** — 在复杂问题分析中，先固定一个参数，让其他浮动
8. **"我有答案，问题是什么？"** — 问题反转策略的反直觉思维框架
9. **高度舞蹈（Altitude Dance）** — 在不同抽象层级之间切换，避免卡在同一个视角
