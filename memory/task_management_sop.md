# task_management_sop — 任务管理与优先级排序
#
# 来源: knowledge-work-plugins/productivity/task-management
# 适用: 从上下文/对话/记忆中整理并排序任务
#
# 流程: 收集 -> 分类 -> 优先级 -> 时间约束 -> 执行顺序

## 1. 收集所有任务
# 来源检查:
#   [当前上下文]: 对话中明确提出的待办事项
#   [工作记忆]: 未完成的任务/中断的工作流
#   [记忆/知识库]: 定期任务/长期项目
#   [工具/系统]: 来自文件/代码/系统状态提示的任务

## 2. 分类
# 两个可选分类轴:
#   [Urgent-Important矩阵]:
#     紧急重要 -> 立即做
#     重要不紧急 -> 规划时间
#     紧急不重要 -> 委托/快速处理
#     不紧急不重要 -> 淘汰
#   [按项目/领域]:
#     每个任务标注所属项目和领域

## 3. 优先级排序
# 每项任务标注:
#   - 影响度(High/Medium/Low)
#   - 紧急度(High/Medium/Low)
#   - 依赖关系(前置任务)
#   - 估计耗时
# 排序规则: 影响度+紧急度 -> 依赖关系 -> 耗时

## 4. 时间约束检查
# - 固定截止时间(今天/本周/本月)
# - 外部依赖(等用户/等系统/等他人)
# - 可用时间窗口(当前连续工作时间)
# - 任务间切换成本(同类任务集中处理)

## 5. 输出执行顺序
# 格式:
#   1. [NOW] 任务名(影响:高, 紧急:高, 约X分钟)
#   2. [NEXT] 任务名(前置:1, 影响:高, 约Y分钟)
#   3. [LATER] 任务名(...)
#   4. [WAIT] 任务名(依赖:用户反馈)
#
# 附带说明:
#   - 为什么是这个顺序(优先级逻辑)
#   - 哪些可以并行执行
#   - 是否需要用户确认

## 6. 更新循环
# 任务完成后:
#   - 从列表中移除
#   - 检查是否有下游任务可解锁
#   - 重排剩余任务顺序
