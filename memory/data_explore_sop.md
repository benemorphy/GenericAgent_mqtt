# data_explore_sop — 结构化数据探索与分析
#
# 来源: knowledge-work-plugins/data/skills/explore-data + analyze
# 适用: 遇到新数据集/回答数据问题
#
# 流程:
#   1. 确定数据源 → 2. 结构探查 → 3. 数据画像 → 4. 列分类 → 5. 深度分析 → 6. 输出报告
#
# 关键原则:
#   - 先探查后分析: 不自以为已知数据形状
#   - 空值率+基数比是快速判断列质量的核心指标
#   - 百分位分析(p1/p5/p95/p99)比均值更能反映数据特征

## 1. 确定数据源
# 数据来源分类处理:
#   [数据仓库连接]: 查询表元数据(列名/类型/描述)
#   [上传文件(CSV/Excel/Parquet/JSON)]: 读取文件, 推断列类型
#   [仅描述]: 提供探查SQL指导
#   [未知]: 询问用户提供表名或上传文件

## 2. 结构探查
# 表级问题:
#   - 行数/列数?  粒度(一行=什么)?  主键是否唯一?
#   - 最后更新时间?  数据追溯范围?
#   - 表大小(从元数据获取)?

## 3. 数据画像(profiling)
# 所有列:
#   空值数/空值率 | 不同值数/基数比 | 最常见值(top5-10) | 最罕见值
# 数值列额外:
#   min/max/mean/median/std | p1/p5/p25/p75/p95/p99 | 零值数
# 时间列额外:
#   日期范围 | 缺失gap检查 | 周期性模式
# 文本列额外:
#   平均长度 | 空字符串率 | 常见模式(邮箱/URL/ID格式)

## 4. 列分类
# 按以下类别标注每列:
#   Identifier   - 唯一键/外键/实体ID
#   Dimension    - 分组建类目(status/type/region)
#   Metric       - 数值度量(revenue/count/duration)
#   Temporal     - 日期时间(created_at/event_date)
#   Text         - 自由文本(description/notes)
#   Boolean      - 真假标志
#   Structural   - JSON/数组/嵌套结构

## 5. 深度分析(按复杂度分级)
# [Quick answer]: 单一指标/简单过滤/事实查询
#   -> 直接SQL查询, 返回数值+简短说明
# [Full analysis]: 多维探索/趋势分析/对比
#   -> 多步SQL探查, 验证异常, 结构化呈现
# [Formal report]: 综合调查+方法论+注意事项+建议
#   -> 完整分析链: 理解问题->探查数据->深度分析->验证->输出
#
# 条件分支:
#   如果查询失败 -> debug重试(检查列名/表引用/方言语法)
#   如果结果异常 -> 先做sanity check再继续

## 6. 输出报告格式
# - 概述(范围/方法/时间/样本量)
# - 发现(按优先级排列, 每条含: 陈述句/证据/置信度)
# - 建议(可操作, 关联发现)
# - 未尽事项(不确定性/后续步骤)
#
# 置信度标注:
#   [High]   - 强证据, 多数据源交叉验证
#   [Medium] - 可信但需用户确认
#   [Low]    - 早期信号/小样本/推测
