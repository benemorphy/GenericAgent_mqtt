# 2026-06-10 Daily Log (续)

## LLM 缓存 Bug 修复

### 背景
缓存在之前的 P1/P2/P3 实现中存在以下问题：

**Bug 1 (P0) - store() 参数错位**
- `_SEMANTIC_CACHE.store(msgs, tuple(collected))` 只传2个参数
- 但 `store()` 签名是 `(self, messages, system, model, response_chunks)` 需要4个
- collected_tuple 被当成 system prompt 传入，TypeError 被 `except: pass` 吞掉
- **导致语义缓存从未成功存储过任何条目**
- 修复: `_SEMANTIC_CACHE.store(msgs, getattr(self, 'system', None), self.model, tuple(collected))`

**Bug 2 (P1) - lookup() 未传 system/model**
- `_SEMANTIC_CACHE.lookup(msgs)` 不传 system/model，降低匹配精度
- 修复: 传 `getattr(self, 'system', None), self.model`

**Bug 3 (P1) - 模块级初始化导致启动延迟**
- `_SEMANTIC_CACHE = get_semantic_cache()` 在模块导入时立即执行
- 替换为惰性初始化: `_SEMANTIC_CACHE = None` + `_ensure_semantic_cache()`
- 首次使用时才加载，import 时间不增加

### 修复文件
- `llmcore.py`: 4处修改 (L33→惰性初始化, L109→_cache_stats_str, L962→lookup传参, L1001→store传参)

### 验证结果
- 编译通过
- store/lookup 端到端正常工作 ✅
- 命中率 100%（单条目测试）
