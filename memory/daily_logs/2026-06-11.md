## 第三轮修复 (2026-06-11 晚) — 管道实例无限创建泄漏

### 问题根源
`server.rs` 的 `run()` 主循环是一个无上限的 `loop { create pipe -> tokio::spawn }`，无实例创建上限控制：

| 阶段 | 现象 |
|------|------|
| 正常 | 每次迭代创建一个新的 Windows Named Pipe 实例 |
| max (255) | `create()` 返回 `ERROR_PIPE_BUSY`，回退 500ms 重试 |
| 内存 | 255 个 pipe 实例句柄 + tokio task 堆栈 + 64KB buffer/个 ≈ 16MB+ 固定开销 |
| 诊断特征 | 进程句柄数缓慢爬升到 ~260 后稳定，进程内存只增不减 |

### 修复方案 (Semaphore 限流)
- 引入 `tokio::sync::Semaphore::new(3)` 限制最大并发实例
- 主循环先 `acquire_owned()` 获取许可，再创建 pipe
- permit 随 tokio::spawn 的 task 生命周期自动 drop 释放
- 达到 3 上限时主循环自然阻塞，不再创建新 pipe

### 涉及变更
- `src/server.rs`：+Semaphore import, +MAX_INSTANCES=3, run() 改实例池模式
