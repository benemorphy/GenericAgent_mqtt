# Agent 行为 Tier 路由 SOP

> 参考 `squilla_router` 的 4 层模型匹配设计
> 目标: 按任务复杂度匹配不同的**推理深度和谨慎程度**

---

## 0. 核心原则

- **不是"工具集不同"**，而是**推理模式不同**——就像不同模型有不同能力侧重
- 简单任务用"flash模式"（快，少思考），复杂任务用"reasoning模式"（慢，多推演）
- 可升级：当前 Tier 无法完成时，升级到更深的推理模式

## 1. Tier 定义

| Tier | 对标模型 | 推理模式 | 思考深度 | 典型场景 |
|------|----------|----------|----------|----------|
| T0 | deepseek-v4-flash | **直答** | 单轮，不展开，信噪比优先 | "你好"、"是/不是"、确认问答 |
| T1 | deepseek-v4-pro | **通用** | 常规推理，1-2步工具 | 读文件、查配置、简单搜索 |
| T2 | deepseek-reasoner | **推理** | 多步推演，调用链追踪 | 代码分析、debug、架构理解 |
| T3 | claude-opus-4.7 | **前沿** | 全面分析，风险推演 | 不可逆操作、新架构设计 |

## 2. 路由规则

### 2.1 自动匹配条件

```
T0 (flash模式):
  - 用户消息 ≤ 5 个词，非命令式开头
  - 明确的是非问
  - 纯打招呼/确认

T1 (通用模式):
  - 单文件读取/搜索
  - 简单状态检查
  - 默认路由（无明确特征时）

T2 (推理模式):
  - 包含"分析"、"debug"、"排查"、"追踪"、"调用链"
  - 多步骤任务 (≥3步)
  - CodeGraph 调用

T3 (前沿模式):
  - 包含"删除"、"移动"、"修改配置"、"不可逆"
  - 跨项目/系统的文件操作
  - 风险未知的新操作
```

### 2.2 升级规则

```
T0 失败 → T1 (需要查文件)
T1 失败 → T2 (需要调用链分析)
T2 失败 2 次 → T3 (全面分析)
T3 失败 → 请求用户干预
不可逆操作 → 直接 T3
```

## 3. 不同推理模式的行为差异

| 维度 | T0 flash | T1 通用 | T2 reasoning | T3 frontier |
|------|----------|---------|--------------|-------------|
| 是否反问确认 | 否 | 仅边界情况 | 关键步骤前确认 | 全程确认 |
| 是否用CodeGraph | 否 | 仅search | callers+callees+impact | 全23工具 |
| 失败重试次数 | 0 | 1次 | 2次后升级 | 1次后求助 |
| 是否写memory | 否 | 仅关键发现 | 全部路径记录 | 完整日志 |
