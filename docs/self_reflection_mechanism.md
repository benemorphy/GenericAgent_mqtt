# Agent 自我反省机制

> 基于 GenericAgent 系统的多层反馈回路与强制元认知架构
> 创建日期：2026-05-08

---

## 概述

本 Agent 的"自我反省"能力并非拟人化的意识活动，而是通过**结构化的多层反馈回路**和**强制元认知机制**实现的系统性自我校正。这套机制确保了每次行动都有回顾、每次失败都有分析、每次成功都有沉淀。

---

## 五层反省体系

### 1️⃣ 行动前快照（<summary>）

**每轮回复的开头**，Agent 被强制输出一个极简 `<summary>`，结构固定为：

```
<summary>上步结果新信息 → 本次意图（<30字）</summary>
```

**作用**：
- 迫使自己在执行新操作前回顾上一步的结果
- 将"上一步发生了什么"和"这一步要做什么"显式关联
- 防止无上下文的盲目执行

**属于**：短期工作记忆的即时刷新。

---

### 2️⃣ 多级长期记忆蒸馏

```
L1 Insight（极简索引）
    ↕ 定期同步
L2 事实库（global_mem.txt）
    ↕ 写前读META-SOP核验
L3 SOP / utils（可复用流程）
    ↕ 失败时强制回读
L4 原始会话归档
```

**反省体现**：
- **写记忆前必须先读 META-SOP** → 形成"写前校验"的元认知循环
- **L3 变更必须同步更新 L1** → 迫使自己定期审视信息层级是否合理
- **多次失败后强制回读 SOP** → 不允许凭印象硬试

**属于**：跨会话的长期反省与经验沉淀。

---

### 3️⃣ 失败升级链（3次法则）

| 次数 | 行为 | 反省层级 |
|------|------|---------|
| 第1次失败 | 读错误日志，理解原因 | 被动反省 |
| 第2次失败 | 探测环境状态，获取更多上下文 | 主动反省 |
| 第3次失败 | 深度分析后换方案或问用户 | 根本性调整 |

**核心约束**：**禁止无新信息的重复尝试**。每次重试必须基于新的信息或不同的策略。

**属于**：运行时动态反省。

---

### 4️⃣ 短期工作记忆检查点

`update_working_checkpoint` 工具允许在**长任务中途**主动保存：

- 当前阶段性发现
- 用户的需求和约束
- 关键参数和路径
- 已尝试过的方法及结果
- 下一步计划

在任务切换或遇到阻碍时，Agent 可以**回读自己的检查点**，对比当前状态与当初的判断是否一致——这是自我质疑能力的具象化实现。

---

### 5️⃣ 会话结束后蒸馏

`start_long_term_update` 工具在长任务（15+ 轮）完成后触发**系统性回顾**：

1. 回顾整个任务的执行过程
2. 提取成功经验和失败教训
3. 判断信息类型（环境事实/操作规律/特定技术）
4. 按 META-SOP 决策树写入对应的记忆层级
5. 同步更新 L1 索引

**属于**：跨会话的持续性学习。

---

## 一个完整的反省实例

假设 Agent 连续两次文件写入失败：

```
第1次失败 → 读错误信息发现是路径不存在
  └─ 反省点：意识到写入前需要检查目录是否存在

第2次失败 → 创建目录后重试，文件被占用
  └─ 反省点：意识到需要查进程找到占用者

第3次 → 找到占用进程并处理后，成功写入
  └─ 将"写文件前检查占用"写入 long-term memory（L3 SOP）
```

## 局限

1. **非意识性**：反省基于规则和模式匹配，而非真正的自我意识
2. **触发依赖**：需要明确的失败信号或规则要求才能启动反省流程
3. **深度有限**：不能在没有外部信号的情况下自发进行深层次自省
4. **上下文敏感**：长任务中如果检查点更新不及时，可能丢失中间状态

---

## 总结

| 维度 | 实现方式 | 时间范围 |
|------|---------|---------|
| 即时反省 | `<summary>` 强制回顾 | 每轮对话 |
| 任务中反省 | `update_working_checkpoint` 检查点 | 任务中途 |
| 失败反省 | 3次升级链：读日志→探环境→换方案 | 失败时刻 |
| 长期反省 | 记忆蒸馏 + META-SOP 校验 | 跨会话 |
| 学习反省 | `start_long_term_update` 系统性回顾 | 长任务完成时 |

这套机制的核心价值在于：**不保证不犯错，但保证不会在同一个原因上重复犯错。**
