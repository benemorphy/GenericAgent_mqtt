# 2 通用智能体
## 2.1 设计原则
上下文信息密度是自进化大语言模型（LLM）智能体的核心要素。基于大语言模型的智能体性能并非仅由上下文长度决定，更根本的是取决于上下文质量。近期研究发现了三种叠加的失效模式，这些模式限制了模型对输入内容的有效利用能力：
1. 模型在处理长序列时会表现出明显的位置偏差：放置在上下文中间的相关信息，其检索难度远高于开头或结尾的信息。
2. 无关内容并非只是被闲置不用，它还会通过将注意力从决策关键证据上转移开，从而主动拉低模型性能。
3. 大语言模型的有效上下文长度远低于其标称窗口大小，这意味着所提供的上下文有一部分在生成过程中实际上无法被访问。

这三种现象在实际应用中相互强化，超过某个临界点后，增加上下文不仅无法提升性能，反而可能导致性能下降。

从上下文工程的角度来看，核心需求与约束为：
- **完整性**：当前决策所需的所有信息都必须明确体现在语境中，防止模型依赖隐含假设或虚构推理。
- **简洁性**：必须剔除无关和冗余的信息，以确保注意力始终集中在决策关键信号上。
- **自然性**：上下文应保持合理的自然度和语义清晰度，避免因过度压缩或人工编码导致模型难以利用。

完整性与简洁性构成了上下文设计的核心权衡，自然性则作为辅助约束。GA的设计核心正是平衡这一矛盾，在系统多个层级系统性优化信息密度。

### 2.1.1 工具最小化
为在任务执行开始前最大化上下文信息密度，GA将工具设计限制在必要的最小集合内。工具过度使用会带来两层系统级成本：
1. 提示词层面：每增加一个工具都会扩大注入上下文的工具模式及指令，持续占用有效上下文预算。
2. 政策层面：扩大行动范围并增加工具选择模糊性，降低规划稳定性，提高执行错误概率。

GA工具集满足**原子性**与**组合泛化**：每个工具具备不可约简特性，复杂行为通过少量原子工具组合实现，无需新增专用接口，让经验整合更轻量。

### 2.1.2 分层记忆
为在任务执行过程中持续保持上下文信息密度，GA避免默认将所有信息作为提示常驻信息，仅保留小型常驻可见层，深层记忆按需访问。
- 常驻层：刻意小型化，仅包含轻量定位信息。
- 深层记忆：以归档或压缩形式存储事实性、程序性知识与历史数据，按需检索进入活跃上下文。

该设计避免记忆持续占用活跃上下文资源，为当前推理与操作保留更多窗口空间。

### 2.1.3 作为经验整合的自我进化
为让上下文信息密度在长期各类任务中持续提升，GA引入自我进化机制，实现跨任务经验整合。
- 不直接记录最优行动序列，而是为未来任务提供更优起点，在重复执行中逐步提升复用效果。
- 不修改基础模型，通过记录与更新模型运行的信息环境实现进化。
- 以选择性整合为核心，优先保留基于成功执行的信息，过滤易变、低验证度或情境性内容。

工具极简性为自我进化创造条件，分层记忆为自我进化提供组织基础。

### 2.1.4 上下文截断与压缩
GA设定低于3万个标记的紧凑上下文预算，着力于信息压缩而非扩展，通过多粒度分层管理历史信息：
1. 采用首尾策略对工具输出进行截断，限制单条消息长度。
2. 对旧消息冗余内容按标签层级压缩，剔除低价值片段。
3. 全局上下文预算耗尽时，按时间顺序删除最早消息。
4. 工作记忆锚定提示词保留任务关键信息。

确保活跃上下文在长周期执行中保持紧凑且与决策相关。

## 2.2 通用智能体概述
通用智能体（GenericAgent，GA）是通用型自进化LLM智能体系统，旨在实现本地计算环境内任务自动化，具备以下特性：
- 模型无关：底层推理引擎（Claude、GPT、Gemini等）可替换，不影响执行逻辑、工具接口与内存架构。
- 统一智能体循环：每一步将全局记忆与当前任务规范结合形成执行上下文，LLM处理后生成输出或工具调用，工具执行结果以结构化信号更新系统状态。
- 两种执行模式：
  1. **交互模式**：处理用户发起的任务，如代码执行、信息检索、文件操作。
  2. **反射模式**：无需用户指令，持续监控环境变化，检测到特定条件自动触发对应任务。

## 2.3 通用智能体的核心组件
### 2.3.1 最小原子工具集
GA工具集由9种原子工具构成，分为五大能力类别，无功能重叠，复杂任务通过组合完成：
| 能力类别 | 工具 | 功能 |
| --- | --- | --- |
| 文件操作 | file_read、file_patch、file_write | 读取、精准编辑、块写入 |
| 代码执行 | code_run | 受控运行时内执行Python/Bash代码 |
| Web交互 | web_scan、web_execute_js | 低成本页面检查、精准浏览器操作 |
| 内存管理 | update_working_checkpoint、start_long_term_update | 短期上下文维护、长期记忆提炼 |
| 人机协作 | ask_user | 需要用户决策时调用 |

**设计优势**：
- 声明、调用与分发分离：以JSONSchema定义工具，统一分发器路由执行。
- 能力边界清晰：严格限定工具权限，提升可控性与可追溯性。
- 工具专属优化：支持分段读取、唯一匹配、DOM结构化提取等，降低令牌消耗。

### 2.3.2 分层内存架构
GA将记忆组织为四层架构，实现信息密度最大化：
1. **L1 索引层**：存储紧凑指针（高频入口、关键词映射、硬约束），作为常驻内存核心，快速导航。
2. **L2 事实层**：存储经验证的长期稳定事实，严格准入，排除瞬态信息。
3. **L3 SOP层**：存储可复用流程性知识（工作流、前置条件、故障处理）。
4. **L4 原始会话归档层**：持久化存储历史会话，用于轨迹重构与审计。

**管理机制**：
- 全局元记忆层：定义记忆图谱、核心规则与更新边界，减少误读与泄露。
- 触发式提交：信息经验证后增量写入L2/L3，避免内存无节制增长。
- L1保持有界：仅记录知识类别存在性，LLM充当解码器实现精准路由。

### 2.3.3 通用智能体的自我进化能力
GA将自我进化实施为透明过程，核心规则如下：
1. **进化策略而非工具**：固定工具层与进化知识层分离，任务能力存储于SOP与可复用脚本。
2. **知识积累：层级记忆**：L1自动追踪新L2事实与L3流程，成功任务永久拓展能力。
3. **质量控制：选择性整合**：仅保留经工具执行验证的信息，丢弃猜测、临时状态与失败分支。
4. **故障处理：分级升级**：
   - 局部调整重试→切换新策略→请求人工干预，避免无限循环。

### 2.3.4 上下文截断与压缩
GA采用字符域启发式方法管理上下文预算，通过四阶段修剪机制控制长度：
1. **工具输出截断**：单工具输出超阈值时保留首尾，替换中间部分。
2. **标签级压缩**：每五轮替换重复工作记忆块为占位符，截断旧消息冗余内容。
3. **消息清理**：超预算时重新压缩并按先进先出删除旧消息。
4. **工作记忆锚定**：每条新消息附加最新对话摘要、轮次编号与关键信息，确保关键内容常驻。

辅助优化：工具模式无变化时用简短提醒替换完整定义，定期重新发送完整模式。

# 3 从极简架构到涌现能力
## 3.1 最小化架构
GA在代码与接口层面实现极致极简：
- **代码极简**：核心代码库约3300行，核心智能体循环仅92行，无重型模块依赖。
- **接口极简**：以自托管CLI为原生执行界面，任务提交、监控、干预均通过CLI完成。

极简设计让子智能体调度、反射模式等高级能力自然涌现，无需新增架构层。

## 3.2 组合能力
基于CLI原生接口，GA无需扩展核心架构即可实现两大高级能力：
### 3.2.1 子智能体调度
父代理通过终端命令启动多个GA实例，子代理为独立进程：
- 上下文天然隔离，子任务互不干扰。
- 支持并行任务的映射归约工作流，父节点合并子进程结果。

### 3.2.2 反射模式
轻量级脚本监控环境条件，满足时自动向CLI发送任务指令，典型应用：
- **看门狗**：监控文件、日志等变化，触发对应任务。
- **定时任务**：按时间规则生成GA任务。

规则脚本独立于智能体，可运行时更新，无需重启核心进程。

## 3.3 自主探索能力
自主探索是子智能体调度与反射模式的结合产物，无需新增架构：
### 3.3.1 技能树
两级结构存储积累技能：类别（web自动化、数据处理等）→具名技能，记录工具脚本与使用次数。

### 3.3.2 触发机制
1. **任务模式**：外部编排器通过文件系统提交任务。
2. **反射模式**：定期轮询回调函数，空闲时触发探索。

### 3.3.3 探索任务生成
课程规划器从**广度、深度、效用、创新性**四个维度加权评分生成任务，确保覆盖多类别。

### 3.3.4 执行与整合
流程：上下文加载→技能搜索→沙盒执行→撰写报告→技能整合，失败实验完整记录。
- 安全约束：文件操作限制在临时目录，禁止访问系统密钥与核心源码。
- 自动注入日志：错误修正方案、用户偏好、成功模式指导后续决策。

### 3.3.5 探索质量评估
基于反思的适配机制：根据任务实际使用率调整评分权重，自动优化探索决策。

### 3.3.6 局限性
- 上下文长度限制：复杂研究任务需跨会话，连续性依赖报告与清单。
- 未经验证的适配：权重调整机制缺乏长期数据验证。
- 手动管理：自我改进日志、技能树高级操作需人工干预。
