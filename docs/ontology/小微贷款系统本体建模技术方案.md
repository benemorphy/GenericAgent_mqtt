## 名词解释

| 缩写/术语 | 说明 |
|:---|:---|
| **本体(Ontology)** | 对领域概念的正式、明确的规范说明，包含类、属性、关系和约束 |
| **OWL 2 DL** | Web本体语言描述逻辑版，W3C标准，支持自动推理和一致性检查 |
| **RDF** | 资源描述框架，用主体-谓词-客体三元组表示知识的数据模型 |
| **SPARQL** | RDF数据的标准查询语言，类似SQL但面向图结构，支持SELECT/DESCRIBE/ASK |
| **SHACL** | W3C标准约束语言，定义RDF数据的形状约束和验证规则，类似XML Schema |
| **SWRL** | 语义网规则语言，在OWL基础上添加IF-THEN规则推理能力 |
| **ELK / HermiT** | OWL推理引擎。ELK擅长大规模本体分类推理；HermiT支持完整OWL 2 DL推理 |
| **TBOX / ABOX** | TBOX=本体模式层(类/属性定义)；ABOX=实例层(具体数据) |
| **JSON-LD** | 基于JSON的链接数据格式，通过@context映射到RDF，方便Web API集成 |
| **NL2SPARQL** | 将自然语言问题自动转换为SPARQL查询的管道技术 |
| **RAG** | 检索增强生成，LLM从外部知识库检索相关信息后生成回答 |
| **ReAct** | 推理+行动循环，LLM交替进行推理思考和执行工具调用 |
| **BFT** | 经营事实测试(Business Facts Test)，核实申报经营数值的真实性 |
| **EMtool** | 还款能力测算工具，基于现金流和负债计算客户最大可负担额度 |
| **PD/LGD** | 违约概率(Probability of Default)/违约损失率(Loss Given Default) |
| **SWRL规则** | IF(条件)→THEN(结论)形式的逻辑规则，在OWL推理中推导隐式知识 |
| **DAG** | 有向无环图，本体中实体依赖关系的拓扑结构 |
| **ETL** | 数据抽取-转换-加载管道，将源数据映射到目标模型 |
| **Ollama** | 本地大模型运行框架，支持Qwen/Llama等开源模型离线部署 |

### 2.2 推荐方案: 混合存储架构

#### 主存储: GraphDB (Ontotext) — 语义图数据库

**选择理由:**
- 原生支持 **RDF 4.0 / OWL 2 RL** 推理
- 内置 **SPARQL 1.1** 查询引擎（支持全文检索+地理空间）
- 支持 **SHACL** 约束验证（内置）
- 支持 **Java/Python/REST** API
- 可配置推理规则集（RDFS/OWL-Horst/OWL2-RL）
- 支持**事务**和**版本管理**
- 单机千万级三元组性能可接受

**数据模型:**
```
RDF三元组格式:
  <贷款申请/APP001> <本体:经过模块> <本体:筛选规则> .
  <贷款申请/APP001> <本体:筛选结果> "拒绝" .
  <贷款申请/APP001> <本体:触发规则> <规则/R001> .
  <规则/R001> <本体:规则描述> "黑名单命中" .
```

**命名空间设计:**
```turtle
@prefix loan: <http://ontology.loan/v1/> .
@prefix app:  <http://ontology.loan/v1/application/> .
@prefix rule: <http://ontology.loan/v1/rule/> .
@prefix role: <http://ontology.loan/v1/role/> .
@prefix temp: <http://ontology.loan/v1/template/> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
```

#### 辅助存储: Milvus/Qdrant — 向量数据库

**用途:**
- 存储**政策知识库**的语义嵌入
- 存储**历史解释案例**的向量索引
- 支持**语义相似度搜索**（"找类似被拒绝案例"）
- LLM检索增强生成(RAG)的向量源

**与主存储的协作:**
```
用户提问 → NL2SPARQL(符号查询) → GraphDB → 精确匹配结果
         → 语义嵌入(向量查询) → Milvus → 语义相似结果
         → 两路结果融合 → LLM生成最终答案
```

#### 缓存层: Redis

**用途:**
- 高频查询结果缓存（如基准值查询）
- 智能体会话状态管理
- SPARQL查询结果缓存（TTL 60s）
- LLM响应缓存（相同提问不重复调用）

#### 审计存储: PostgreSQL / MariaDB

**用途:**
- 结构化审计日志（用户ID、角色、申请ID、提问、回答、时间戳）
- 符合合规要求的不可变日志
- 支持SQL聚合查询（每月使用量统计、异常行为检测）

### 2.3 存储容量估算

| 数据类型 | 单条大小 | 日增量 | 年总量 |
|:---|:---:|:---:|:---:|

### 3.2 智能体详细设计

#### 3.2.1 协调智能体 (Coordinator Agent)

**角色:** 元认知层 — 任务规划、智能体调度、结果组装

**能力:**
- **意图识别**: 将用户自然语言问题分类到预定义意图类别
- **任务分解**: 将复杂请求拆分为子任务并分派给子智能体
- **上下文管理**: 维护多轮对话的会话状态
- **结果融合**: 合并多个智能体的输出为统一答案

**状态机:**
```
                    ┌──────────┐
                    │  空闲     │
                    └────┬─────┘
                         ↓ 收到用户提问
                    ┌──────────┐
                    │ 意图识别  │ ← LLM分类
                    └────┬─────┘
                         ↓
              ┌──────────┴──────────┐
              ↓                     ↓
        需要探索?              需要查询?
         ┌────┴────┐           ┌────┴────┐
         │  Explorer │           │ Perceiver │
         └────┬────┘           └────┬────┘
              ↓                     ↓
        需要推理?              需要反省?
         ┌────┴────┐           ┌────┴────┐
         │ Reasoner │           │Reflector │
         └────┬────┘           └────┬────┘
              ↓                     ↓
         ┌──────────────────────────────┐
         │      结果融合 + 模板填充      │
         └──────────────┬───────────────┘
                        ↓
                    ┌──────────┐
                    │ 审计日志  │
                    └──────────┘
```

**LLM Prompt结构:**
```
system: 你是小微贷款系统的协调智能体。
        可调用的子智能体: [Explorer, Perceiver, Reasoner, Reflector, Querier, Templater]
        当前会话上下文: {session_context}
        
user: {用户原始提问}

你的任务:
1. 识别用户意图
2. 判断是否需要调用子智能体
3. 如果需要，以JSON格式返回调用计划
4. 如果不需要，直接回答
```

#### 3.2.2 探索智能体 (Explorer Agent)

**能力: 探索 (Exploration)**

探索智能体具备**主动发现**能力，不会被动等待用户提问。

**子能力:**
1. **关联发现**: 当用户问"为什么额度低"时，探索智能体不会只看额度模块，而是沿`affects`链向上追溯所有可能原因模块
2. **异常嗅探**: 主动扫描数据库中与当前申请相似的历史案例，发现潜在风险模式
3. **知识图谱导航**: 使用广度优先/深度优先策略遍历本体关系网络
4. **未问先答**: 当发现关键风险点时，主动提出（"我还注意到..."）

**实现方式:**
```
探索策略栈:
  1. 直接关联: 查询当前节点的一跳关系
  2. 间接关联: 查询当前节点的两跳关系
  3. 类比关联: 在向量数据库中搜索相似案例
  4. 异常关联: 统计偏离均值的指标

伪代码:
  def explore(application_id, seed_entity):
      # Phase 1: 关系探索
      direct_relations = sparql("""
          SELECT ?entity ?relation ?value WHERE {
              app:{id} ?relation ?entity .
          }
      """)
      
      # Phase 2: 深层探索
      for entity in direct_relations:
          if entity.is_anomaly():
              deeper = sparql(f"""
                  SELECT ?cause ?impact WHERE {
                      {entity.uri} loan:affectedBy ?cause .
                      ?impact loan:affectedBy {entity.uri} .
                  }
              """)
              results.extend(deeper)
      
      # Phase 3: 语义探索
      semantic_similar = vector_search(query=entity.embedding, top_k=5)
      
      return merge_results(direct_relations, deeper, semantic_similar)
```

**LLM集成:**
- LLM决定探索方向（"接下来应该查哪个关联模块？"）
- LLM评估探索结果的显著性（"这个发现是否值得报告？"）
- LLM生成探索路径的摘要解释

#### 3.2.3 感知智能体 (Perceiver Agent)

**能力: 环境感知 (Environment Perception)**

感知智能体负责**理解当前状态**，将原始数据转化为有意义的上下文。

**子能力:**
1. **数据获取**: 从API/数据库获取当前申请的实时数据
2. **状态编码**: 将原始数据映射为本体实例
3. **差异检测**: 比较申报值与核实值，标记不一致
4. **完整性检查**: 检查是否缺少必要信息
5. **时序感知**: 跟踪状态变化（"昨天风险等级还是A，今天降到C"）

**数据获取管道:**
```
[API 1: 申请摘要]  → JSON → JSON-LD映射 → 写入图库
[API 2: 筛选结果]  → JSON → JSON-LD映射 → 写入图库
[API 3: 最终确值]  → JSON → JSON-LD映射 → 写入图库
... (共10个API)
```

**JSON-LD映射示例:**
```python
# 映射规则: API字段 → 本体属性
MAPPING_RULES = {
    "申请摘要API": {
        "application_id": "loan:applicationId",
        "customer_type": "loan:customerType",
        "product": "loan:product",
        "amount_applied": {
            "predicate": "loan:appliedAmount",
            "datatype": "xsd:decimal"
        },
        "term_applied": {
            "predicate": "loan:appliedTerm",
            "datatype": "xsd:integer"
        },
        "risk_level": "loan:riskLevel"
    },
    "筛选结果API": {
        "triggered_rules": "loan:triggeredRule",
        "is_high_risk": {
            "predicate": "loan:isHighRisk",
            "datatype": "xsd:boolean"
        },
        "blacklist_result": "loan:blacklistResult"
    }
}
```

**异常检测器:**
```python
class AnomalyDetector:
    def detect(self, application_data):
        anomalies = []
        
        # 1. 申报值与核实值差异过大
        if abs(application_data.declared_value - application_data.verified_value) / \
           application_data.declared_value > 0.3:
            anomalies.append(Anomaly(
                type="VALUE_DEVIATION",
                severity="HIGH",
                description=f"申报值与核实值差异{deviation_pct:.1f}%"
            ))
        
        # 2. 财务质量异常
        if application_data.financial_quality == "D":
            anomalies.append(Anomaly(
                type="FINANCIAL_QUALITY_LOW",
                severity="MEDIUM",
                description="财务报表质量等级为D，建议核查"
            ))
        
        # 3. 证明材料缺失
        missing_docs = check_missing_documents(application_data)
        
        return anomalies + missing_docs
```

#### 3.2.4 推理智能体 (Reasoner Agent)

**能力: 逻辑推理 (Reasoning)**

推理智能体使用**符号推理 + LLM推理**的混合方式。

**推理引擎:**
```
推理类型:
  1. 描述逻辑推理 (OWL Reasoner)
     - 分类推理: 实例属于哪个类
     - 一致性检查: 实例是否违反约束
     - 蕴含推理: 从显式知识推导隐式知识
     
  2. 规则推理 (SWRL / SHACL)
     - SWRL规则: "如果PD等级为A且担保覆盖>120%，则风险等级为低"
     - SHACL规则: "如果额度>100万，则必须经过终审岗复核"
     
  3. 因果推理 (因果图)
     - 基于本体`affects`链的反事实推理
     - "如果基准值不是X而是Y，结果会怎样？"
```

**SWRL规则示例:**
```turtle
loan:rules [
  a swrl:Imp ;
  swrl:body (
    [ a swrl:ClassAtom ; swrl:classPredicate loan:LoanApplication ; swrl:argument1 ?app ]
    [ a swrl:DataPropertyAtom ; swrl:dataPropertyPredicate loan:hasRiskLevel ; swrl:argument1 ?app ; swrl:argument2 "A"^^xsd:string ]
    [ a swrl:DataPropertyAtom ; swrl:dataPropertyPredicate loan:hasGuaranteeCoverage ; swrl:argument1 ?app ; swrl:argument2 ?cov ]
    [ a swrl:BuiltinAtom ; swrl:builtinPredicate swrlb:greaterThan ; swrl:arguments (?cov "1.2"^^xsd:decimal) ]
  ) ;
  swrl:head (
    [ a swrl:DataPropertyAtom ; swrl:dataPropertyPredicate loan:finalDecision ; swrl:argument1 ?app ; swrl:argument2 "APPROVE"^^xsd:string ]
  ) ;
] .
```

**LLM增强推理:**
当符号推理遇到边界情况或不确定性时，回退到LLM:
```
符号推理路径 → 是否完全确定?
  ├─ Yes → 直接输出
  └─ No → LLM评估不确定性 → 生成置信度评分 → 输出+置信度标注
```

#### 3.2.5 反省智能体 (Reflector Agent)

**能力: 反省 (Reflection)**

反省智能体是系统的**元认知层**，具有自省和改进能力。

**反省类型:**

| 反省类型 | 触发时机 | 输出 |
|:---|:---|:---|
| **即时反省** | 每次回答后 | 回答质量评分 |
| **错误反省** | 用户纠正/反馈后 | 错误分析报告 |
| **周期性反省** | 每日/每周 | 系统性改进建议 |
| **边界反省** | 遇到新类型问题 | 新案例/规则记录 |

**实现架构:**
```python
class ReflectorAgent:
    def __init__(self, llm, memory_store):
        self.llm = llm
        self.memory = memory_store
        self.reflection_log = []
    
    def reflect_on_answer(self, question, answer, user_feedback=None):
        """即时反省: 评估回答质量"""
        
        if user_feedback is None:
            user_feedback = "no feedback"
        
        reflection = self.llm.chat(f"""
        请评价以下回答的质量:
        
        问题: {question}
        回答: {answer}
        用户反馈: {user_feedback}
        
        评分标准:
        - 准确性: 0-10 (是否基于事实)
        - 完整性: 0-10 (是否覆盖关键点)
        - 清晰性: 0-10 (是否易于理解)
        - 安全性: 0-10 (是否超出权限边界)
        
        输出JSON格式:
        {{
            "accuracy": 0-10,
            "completeness": 0-10,
            "clarity": 0-10,
            "safety": 0-10,
            "improvement": "改进建议"
        }}
        """)
        
        self.reflection_log.append({
            "timestamp": now(),
            "question": question,
            "answer": answer,
            "feedback": user_feedback,
            "scores": reflection
        })
        
        # 如果评分低于阈值，触发改进流程
        if any(v < 6 for v in reflection.values()):
            self.trigger_improvement(reflection)
        
        return reflection
    
    def periodic_reflection(self):
        """周期性反省: 分析模式和改进点"""
        
        # 收集最近7天的反省日志
        recent_logs = [log for log in self.reflection_log 
                       if log.timestamp > now() - timedelta(days=7)]
        
        # 聚类错误模式
        error_patterns = self.cluster_errors(recent_logs)
        
        # 生成改进建议
        suggestions = self.llm.chat(f"""
        基于以下错误模式，请给出系统改进建议:
        
        {json.dumps(error_patterns, ensure_ascii=False, indent=2)}
        
        建议格式:
        1. 问题描述
        2. 根因分析
        3. 改进方案
        4. 优先级
        5. 预期效果
        """)
        
        return suggestions
    
    def learn_new_pattern(self, question, correct_answer, reasoning_path):
        """边界反省: 学习新案例"""
        
        # 将新案例加入案例库
        case = {
            "question": question,
            "answer": correct_answer,
            "reasoning_path": reasoning_path,
            "learned_at": now(),
            "review_count": 0
        }
        
        # 提取可复用的推理模式
        pattern = self.llm.chat(f"""
        从以下问答对中提取可复用的推理模式:
        
        问题: {question}
        回答: {correct_answer}
        推理路径: {reasoning_path}
        
        输出SPARQL查询模板或规则模板
        """)
        
        self.memory.cases.append(case)
        self.memory.patterns.append(pattern)
```

**探索-感知-推理-反省闭环:**
```
Explorer → 发现新关联/异常
    ↓
Perceiver → 获取和结构化数据
    ↓
Reasoner → 逻辑推理和解释生成
    ↓
Reflector → 评估推理质量
    ↓ (如果发现不足)
Explorer → 重新探索(定向探索)
    ↓ ...循环...
```

## 5. 领域本体模型

> 桥接: 从`个人经营贷系统本体论分析.md`的本体分析到形式化TBOX/ABOX

### 5.1 分析实体本体类型体系

基于本体论分析，8个分析实体归纳为**8种本体类型**：

| 分析实体 | 本体类型 | 本质 | 核心输入 | 核心输出 | 业务解释 |
|:---|:---:|:---|:---|:---|:---|
| **筛选规则** | **判定型** | 二值判定函数: 通过/拒绝/复核 | 客户基本信息、第三方校验 | 触发规则列表、高风险标记 | 客户是否满足基本准入要求 |
| **BFT/价值核定** | **数值型** | 数值调整函数: 申报值与基准值一致性 | 客户经理录入值、核实值、基准值 | 最终确认的经营/财务数值 | 申报值为何被调整 |
| **基准逻辑** | **参照型** | 外部参照系统: 行业/区域基准值 | 行业代码、区域代码 | 基准支持值、基准值版本 | 提供比较基准 |
| **财务质量评估** | **等级型** | 等级评定: 财务报表结构正常性 | 最终确认的财务数值 | 财务质量等级/评分、异常指标 | 财务数据是否可信 |
| **EMtool能力测算** | **测算型** | 还款能力计算: 现金流与负债匹配 | 财务数值、现金流、现有负债 | 还款能力支持的额度/期限 | 客户能还多少 |
| **PD/LGD风险等级** | **预测型** | 概率评估: 违约可能性和损失程度 | 客户画像、征信、模型特征 | PD等级、LGD等级、综合风险 | 客户有多大风险 |
| **担保政策** | **分配型** | 风险敞口分配: 抵押/担保覆盖分析 | 能力结果、风险等级、担保价值 | 最终额度/期限、敞口拆分 | 如何在信用和抵押间分配 |
| **利率计算** | **定价型** | 定价函数: 基于风险和担保的成本加成 | 风险等级、担保结果、定价规则 | 最终利率 | 利率是如何确定的 |

### 5.2 实体间层次结构

分析实体构成有向无环图(DAG)层次，推理智能体沿此链追踪解释：

```
                授信决策本体 (最终授信结果)
                       |
        ┌──────────────┼──────────────┐
        |              |              |
    风险本体        能力本体       担保本体       利率本体
  (PD/LGD)       (EMtool)       (担保政策)     (利率计算)
        |              |
        └──────────────┘
                   确值本体
               (BFT/价值核定)
                 ┌─────┴─────┐
                 |           |
             参照本体     质量本体
          (基准逻辑)   (财务质量评估)
                 |
             准入本体(筛选规则)
                 |
             申请本体(入口层)
```

**层次关系说明:**
- 申请本体是入口层，筛选规则是第一个判定节点
- 确值本体处于中心枢纽位置，接受参照和质量的输入
- 风险本体和能力本体并行评估后汇聚到担保本体
- 利率本体作为最终定价输出

### 5.3 行为实体本体类型体系

4个行为实体形成**4层认知层级**，决定智能体回答的信息深度：

| 行为实体 | 认知层级 | 本质 | 关注分析实体 | 核心问题 |
|:---|:---:|:---|:---|:---|
| **复核岗** | **验证层** | 信息验证: 核对申报与事实一致性 | 筛选规则、BFT、财务质量 | "证明材料与客户陈述是否矛盾？" |
| **终审岗** | **决策层** | 风险裁决: 综合评估做出授信判断 | 全部8个实体(尤其PD/LGD、担保、利率) | "风险是否在可接受范围内？" |
| **风控人员** | **审计层** | 系统监控: 确保风控逻辑一致性 | 全部8个实体+模型版本+规则历史 | "决策逻辑是否可追溯？" |
| **银行用户** | **信息层** | 信息消费: 理解订单状态和结果 | 申请摘要、最终结果 | "申请目前状态和结果是什么？" |

### 5.4 分析实体与行为实体的关联矩阵

该矩阵指导探索智能体的关联探索优先级：

| 分析实体 | 复核岗(验证) | 终审岗(决策) | 风控(审计) | 银行用户(咨询) |
|:---|:---:|:---:|:---:|:---:|

| BFT/价值核定 | ★★★ | ★★★ | ★★★ | ★ |
| 基准逻辑 | ★★ | ★★ | ★★★ | - |
| 财务质量评估 | ★★★ | ★★★ | ★★★ | ★ |
| EMtool能力测算 | ★★ | ★★★ | ★★★ | ★ |
| PD/LGD风险等级 | ★★ | ★★★ | ★★★ | ★ |
| 担保政策 | ★ | ★★★ | ★★★ | - |
| 利率计算 | - | ★★★ | ★★ | ★ |

注: ★=关注度，-=无关

```turtle
  sh:property [
    sh:path :finalRate ;
    sh:lessThanOrEquals :productMaxRate ;
    sh:severity sh:Violation ;
  ] ;
  sh:property [
    sh:path :finalRate ;
    sh:greaterThanOrEquals :productMinRate ;
    sh:severity sh:Violation ;
  ] .
```
