## 一、本体论框架概述

本体论(Ontology)分析从**概念化(Conceptualization)**、**形式化(Formalization)**、**层次化(Hierarchy)** 和 **关系化(Relations)** 四个维度，
对小微贷款系统的分析实体与行为实体进行结构化建模。

## 二、分析实体 (Analysis Entities) 本体

分析实体是系统中**被操作、被评估、被计算**的客观对象。每个实体具有属性、状态和行为。

### 2.1 筛选规则 — 准入本体

| 维度 | 描述 |
|------|------|
| **本质** | 二值判定函数: 通过/拒绝/人工复核 |
| **输入属性** | 客户基本信息、第三方校验结果、产品准入条件 |
| **输出属性** | 触发规则列表、高风险标记、目标客群校验、黑名单结果 |
| **影响范围** | 提前终止流程或进入下一阶段 |
| **业务解释** | 客户是否满足基本产品及风险准入要求 |
| **本体类型** | **判定型实体** — 产生布尔决策 |

### 2.2 BFT/价值核定 — 确值本体

| 维度 | 描述 |
|------|------|
| **本质** | 数值调整函数: 申报值与基准值的一致性检验 |
| **输入属性** | 客户经理录入值、核实值、基准值、支持性证明材料 |
| **输出属性** | 最终确认的经营/财务数值 |
| **影响范围** | 调整申报值，供后续模块使用 |
| **业务解释** | 申报值为何被调整，为何选用某个最终数值 |
| **本体类型** | **数值型实体** — 产生确定数值 |

### 2.3 基准逻辑 — 参照本体

| 维度 | 描述 |
|------|------|
| **本质** | 外部参照系统: 行业/区域基准值 |
| **输入属性** | 行业代码、区域代码、适用字段 |
| **输出属性** | 基准支持值、基准值版本、生效日期 |
| **影响范围** | 为BFT提供参照基准 |
| **本体类型** | **参照型实体** — 产生比较基准 |

### 2.4 财务质量评估 — 质量本体

| 维度 | 描述 |
|------|------|
| **本质** | 等级评定函数: 财务报表结构正常性判断 |
| **输入属性** | 最终确认的财务报表数值 |
| **输出属性** | 财务质量等级/评分、异常指标、财报质量结果 |
| **影响范围** | 限制贷款额度/期限或要求额外复核 |
| **本体类型** | **等级型实体** — 产生质量等级 |

### 2.5 EMtool 能力测算 — 能力本体

| 维度 | 描述 |
|------|------|
| **本质** | 还款能力计算函数: 现金流与负债的匹配分析 |
| **输入属性** | 最终确认的财务数值、现金流/月可支、现有负债、产品参数 |
| **输出属性** | 还款能力支持的贷款额度/期限 |
| **影响范围** | 显示还款能力是否支持申请的金额和期限 |
| **本体类型** | **测算型实体** — 产生能力上限 |

### 2.6 违约概率/违约损失率风险等级 — 风险本体

| 维度 | 描述 |
|------|------|
| **本质** | 概率评估函数: 客户未来违约可能性和损失程度预测 |
| **输入属性** | 客户画像、财务数据、征信数据、申请数据、其他模型特征 |
| **输出属性** | PD等级、LGD等级、综合风险等级、可接受的额度×期限情景 |
| **影响范围** | 可能限制或拒绝某些贷款额度/期限组合 |
| **本体类型** | **预测型实体** — 产生风险概率 |

### 2.7 担保政策 — 担保本体

| 维度 | 描述 |
|------|------|
| **本质** | 风险敞口分配策略: 抵押/担保覆盖分析 |
| **输入属性** | 还款能力结果、PD/LGD等级、财务质量结果、抵押/担保价值、政策限制 |
| **输出属性** | 最终贷款额度/期限、有抵押/无抵押拆分、覆盖结果 |
| **影响范围** | 整合各项限制，生成最终风险敞口结构 |
| **本体类型** | **分配型实体** — 产生敞口分配 |

### 2.8 利率计算 — 定价本体

| 维度 | 描述 |
|------|------|
| **本质** | 定价函数: 基于风险和担保的成本加成 |
| **输入属性** | 风险等级、抵押/担保结果、产品定价规则 |
| **输出属性** | 最终利率 |
| **影响范围** | 在产品政策范围内确定最终定价 |
| **本体类型** | **定价型实体** — 产生价格 |

## 三、分析实体本体的层次结构

```
                授信决策本体 (最终授信结果)
                       |
        ┌──────────────┼──────────────┐
        |              |              |
    风险本体        能力本体       担保本体       利率本体
  (PD/LGD)       (EMtool)       (担保政策)     (利率计算)
        |              |
        └──────────────┘
                   确值本体
               (BFT/价值核定)
                 ┌─────┴─────┐
                 |           |
             参照本体     质量本体
          (基准逻辑)   (财务质量评估)
                 |
             准入本体(筛选规则)
                 |
             申请本体(入口层)
```

**层次关系说明:**
- 申请本体是入口层，筛选规则是第一个判定节点
- 确值本体处于中心枢纽位置，接受参照和质量的输入
- 风险本体和能力本体并行评估后汇聚到担保本体
- 利率本体作为最终定价输出

## 四、行为实体 (Behavior Entities) 本体

行为实体是系统中**执行操作、做出判断、使用结果**的主体。每个实体具有角色、权限、认知层级和操作范围。

### 4.1 复核岗 — 验证者本体

| 维度 | 描述 |
|------|------|
| **本质** | 信息验证角色: 核对申报与事实的一致性 |
| **关注重点** | 订单事实、证明材料缺口、矛盾点及核验重点 |
| **关注分析实体** | 筛选结果、BFT/价值核定、财务质量、证明材料 |
| **操作模式** | 对比验证 — 申报信息 vs 核实信息 vs 证明材料 |
| **认知层级** | **验证层**: 关注"是否一致" |
| **核心问题** | "证明材料与客户陈述是否矛盾？" |

### 4.2 终审岗 — 决策者本体

| 维度 | 描述 |
|------|------|
| **本质** | 风险裁决角色: 综合评估后做出最终授信判断 |
| **关注重点** | 主要风险点、模型结果、限制条件及最终决策逻辑 |
| **关注分析实体** | 全部8个实体，特别是PD/LGD、担保政策、利率 |
| **操作模式** | 综合评估 — 权衡风险-收益-政策约束 |
| **认知层级** | **决策层**: 关注"是否可行" |
| **核心问题** | "风险是否在可接受范围内？" |

### 4.3 风控人员 — 审计者本体

| 维度 | 描述 |
|------|------|
| **本质** | 系统监控和追溯角色: 确保风控逻辑一致性 |
| **关注重点** | 规则引用、基准值逻辑、模型版本、计算追溯及数据血缘 |
| **关注分析实体** | 全部8个实体 + 模型版本 + 规则历史 |
| **操作模式** | 追溯分析 — 从结果反向追踪计算路径 |
| **认知层级** | **审计层**: 关注"是否正确" |
| **核心问题** | "决策背后的逻辑和证明材料是否可追溯？" |

### 4.4 银行用户 — 咨询者本体

| 维度 | 描述 |
|------|------|
| **本质** | 信息消费角色: 需要理解订单状态和结果 |
| **关注重点** | 笼统的证明材料要求和非敏感性解释 |
| **关注分析实体** | 申请摘要、最终结果 |
| **操作模式** | 查询理解 — 获取简明解释 |
| **认知层级** | **信息层**: 关注"是什么" |
| **核心问题** | "申请目前的状态和结果是什么？" |

## 六、核心关系网络

### 6.1 数据流关系
```
客户申报值 → [BFT/基准逻辑] → 最终确值 → [EMtool/PD/LGD] → [担保] → [利率]
                   ↑                   ↑
         [财务质量评估]          [证明材料]
```

### 6.2 解释链本体 (通用输出逻辑)
```
事实/数据 → 模型或政策逻辑 → 风险点或限制条件 → 结论
```
这构成了一个**因果链本体**: 每个分析实体的输出都可以沿着此链展开解释。

### 6.3 权限层级
```
银行用户 → 信息层(笼统解释)
复核岗   → 验证层(事实与材料对比)
终审岗   → 决策层(风险权衡)
风控人员 → 审计层(全链路追溯)
```

### 6.4 意图-API路由关系
```
用户问题 → AI意图识别 → API选择 → 数据获取 → 政策知识 → 模板应用 → 答案
```

## 七、本体论总结

| 维度 | 分析实体 | 行为实体 |
|:---|:---|:---|
| **定义** | 被操作和被评估的客观对象 | 执行操作和做出判断的主观主体 |
| **实例数** | 8个 | 4个 |
| **本体类型** | 判定型/数值型/参照型/等级型/测算型/预测型/分配型/定价型 | 验证者/决策者/审计者/咨询者 |
| **层次** | 从入口到输出呈递进层次 | 从信息层到审计层呈递进权限 |
| **关系** | 数据传递、因果链、约束限制 | 关注度矩阵、权限层级、解释深度 |
| **核心矛盾** | 申报值与真实值的偏差(确值调整) | 风险与收益的平衡(授信决策) |
| **系统约束** | 智能助手不可做授信决策，仅解释 | AI只能从已批准的API和数据视图中选择 |
