# 本体论模型输入输出说明

> 说明: 本体模型输入哪些实体信息，输出什么成果
> 日期: 2026-05-25

---

## 一、输入（喂给本体的实体信息）

本体模型本身不直接接入原始数据，通过**感知智能体**将现有系统的**API数据**映射为**本体实例**。

### 1.1 8个分析实体 — 每个审批单在各个模块的产出

| 实体 | 输入数据 | 来源 |
|:---|:---|---:|
| **筛选规则** | 客户基本信息、第三方校验结果、命中规则列表、通过/拒绝标志 | API: 筛选引擎 |
| **BFT/价值核定** | 业主申报值、客户经理核实值、调整后确值、调整原因代码 | API: 价值核定 |
| **基准逻辑** | 行业基准值、区域基准值、客户偏离度、基准来源版本 | API: 基准库 |
| **财务质量评估** | 财务报表条目、结构正常性评分、资产负载率趋势 | API: 财务分析 |
| **EMtool能力测算** | 月均现金流、现有负债、测算最大额度、负债率 | API: 能力测算 |
| **PD/LGD风险等级** | 违约概率PD、违约损失率LGD、风险等级标签 | API: 风险模型 |
| **担保政策** | 担保类型、担保覆盖金额、担保率、担保方信息 | API: 担保系统 |
| **利率计算** | 基础利率、风险溢价、担保折扣、最终利率、利息总额 | API: 定价引擎 |

### 1.2 4个行为实体 — 角色与操作

| 实体 | 输入数据 | 来源 |
|:---|:---|---:|
| **复核岗** | 验证结果、标记的异常项、复核意见、复核时间 | 用户操作日志 |
| **终审岗** | 终审决策(通过/拒绝/条件)、审批意见、审批时间 | 用户操作日志 |
| **风控人员** | 抽查样本、发现问题、整改要求 | 审计系统 |
| **银行用户** | 查询操作、关注焦点、咨询问题 | 系统日志 |

### 1.3 关系数据 — 实体间的连接

| 关系 | 输入内容 | 示例 |
|:---|:---|---:|
| `affects` 影响 | 一个实体输出如何影响下一个实体 | BFT确值 → EMtool额度 |
| `concerns` 关注 | 行为实体关注哪些分析实体 | 复核岗 → 筛选规则 |
| `tracesTo` 溯源 | 审批单到各分析实体的追溯指针 | LOAN-001 → 筛选结果ID |

## 二、输出（从本体模型产出的成果）

### 2.1 服务层产出（API形式）

| 服务 | 输出内容 | 查询逻辑 |
|:---|:---|---:|
| **决策追溯** | 单个申请的完整链路及每个节点值 | `?app :tracesTo ?entity` 沿 `affects`链遍历 |
| **约束验证** | 是否满足所有SHACL规则 | SHACL验证引擎 |
| **异常检测** | 高风险组合标记 | 推理智能体模式匹配 |
| **客群画像** | 按维度聚合分布 | GROUP BY查询 |
| **影响分析** | 变更某参数影响的申请清单 | 条件查询 |

### 2.2 应用层产出（面向用户）

| 产出 | 形式 | 用户 | 价值 |
|:---|:---|:---|:---|
| **智能解释** | 自然语言报告 | 复核岗/终审岗 | 减少80%翻查时间 |
| **运营Dashboard** | Web可视化面板 | 管理层/风控 | 运营健康度一目了然 |
| **运营周报** | PDF自动生成 | 管理层 | 数据驱动决策 |
| **监管报表** | Excel自动输出 | 合规 | 3天→30分钟 |
| **被误拒召回清单** | 推荐重新评估名单 | 风控 | 增加有效贷款存量 |
| **知识更新告警** | 基准/策略过时通知 | 运营 | 保持数据时效性 |

### 2.3 核心输出示例

```
 ┌─────────────────────────────────────────────────────────┐
 │ 申请 LOAN-2026-0515-XXXXX 额度低的原因:                │
```

## 四、一句话总结

> **输入** = 现有系统每个审批单在 **8个分析模块**的API产出数据（值+状态+原因）+
> **4个角色**的操作记录 + 实体间的**关系链路**
>
> **输出** = 从"硬编码API路由"升级为"**可查询、可推理、可验证**的知识服务"：
> 可解释的每一步决策原因、自动化的合规验证、主动发现的异常模式和被误拒客群
