## 2. 分层目标详解

### 2.1 核心层: 风险控制

#### 2.1.1 从"黑箱决策"到"可解释决策"

当前系统的问题:
- 复核岗看到"额度低"，需要翻查5-8个模块才能理解原因
- 终审岗做决策时，依赖个人经验而非数据链路
- 风控审计需要数月才能完成一轮检查

本体模型带来的改变:

```
当前(硬编码路由): 
  申请 → 额度计算结果 → 复审人员逐模块翻查

改造后(本体推理):
  申请 → 本体验证(SHACL) → 自动解释链追踪
       → 复核智能体生成解释报告
       → 终审智能体标记风险点
       → 审计智能体记录完整因果图
```

#### 2.1.2 不良贷款的事前预判

通过`affects`链和约束规则，在审批阶段自动识别高风险组合:

```sparql
# 找出"高PD/LGD + 弱担保 + 宽松筛选"的组合
SELECT ?app ?pd_score ?guarantee ?screen_result
WHERE {
  ?app :hasRiskRating ?rating .
  ?rating :pdScore ?pd_score .
  FILTER(?pd_score > 0.6)
  ?app :hasGuarantee ?guar .
  ?guar :coverage ?cov .
  FILTER(?cov < 0.4)
  ?app :hasScreening ?screen .
  ?screen :result "通过" .
} ORDER BY DESC(?pd_score)
```

### 2.2 效率层: 运营优化

#### 2.2.1 审批时效分析

本体追踪每个申请在各分析实体间的停留时间:

```
时间线本体:
  申请 → 筛选(2s) → 价值核定(5min) → 基准(1s) 
       → 财务质量(3min) → EMtool(2s) → ...
       
瓶颈发现: 价值核定和财务质量评估占用80%的人工时间
优化方向: 这两个模块的AI辅助自动化
```

#### 2.2.2 标准化率提升

SHACL约束确保每个审批都经过完整的链路:

```turtle
:CompletePathShape a sh:NodeShape ;
  sh:targetClass :LoanApplication ;
  sh:property [
    sh:path (:tracesTo)+ ;  # 0次或多次
    sh:qualifiedValueShape [
      sh:class :ScreeningRule ;
    ] ;
    sh:qualifiedMinCount 1 ;  # 至少1次筛选
  ] ;
  sh:property [
    sh:path (:tracesTo)+ ;
    sh:qualifiedValueShape [
      sh:class :ValueVerification ;
    ] ;
    sh:qualifiedMinCount 1 ;  # 至少1次价值核定
  ] ;
  # ... 同样约束其他6个实体
```

### 2.3 增长层: 业务拓展

#### 2.3.1 有效贷款存量的精准提升

通过分析历史拒绝案例，发现"被误拒"的客群模式:

| 发现模式 | 当前状态 | 本体模型贡献 | 预期影响 |
|:---|:---|:---|:---:|
| 财务质量B-但BFT确值后改善 | 自动拒绝 | 追踪确值后改善路径 | 召回5-8%优质客群 |
| 担保充足但PD模型高估 | 一刀切拒绝 | 比较担保覆盖与PD预测的冲突 | 释放10-15%担保充足客户 |
| 行业基准过时导致误判 | 无法发现 | 基准逻辑版本追踪+时态推理 | 更新基准后提升准确性 |

#### 2.3.2 产品匹配优化

通过客户属性与产品规则的自动本体匹配:

```sparql
# 找到适合某客户的隐藏产品
SELECT ?product ?matchScore WHERE {
  :Customer_123 :hasIndustry "餐饮" .
  :Customer_123 :annualRevenue ?rev .
  
  ?product a :LoanProduct .
  ?product :industryRule ?indRule .
  FILTER(CONTAINS(?indRule, "餐饮"))
  ?product :maxRevenue ?maxRev .
  FILTER(?rev < ?maxRev)
  
  # 计算匹配度
  BIND(IF(?rev > 1000000, 0.9, 0.7) AS ?matchScore)
} ORDER BY DESC(?matchScore)
```

### 5.2 运营建议样例

#### 场景1: 发现基准逻辑过时

```
[探索智能体发现]
  餐饮行业的基准逻辑数据来源为2023Q4，已有18个月未更新
  同期，该行业的拒绝率从12%上升到23%
  
[推理智能体分析]
  基准过时导致37%的餐饮行业申请被低估经营能力
  这批被拒客群中，有15%在其他银行的表现为正常还款
  
[运营建议]
  1. 紧急更新餐饮行业基准数据（优先级P0）
  2. 对受影响的历史申请进行批量重新评估
  3. 建立基准数据的自动时效性监控机制
```

#### 场景2: 发现被误拒的优质客群

```
[探索智能体发现]
  以下模式被高频拒绝: 
    财务质量B级、EMtool通过、PD<0.4、贷款期限<3年
  
[推理智能体分析]
  这类客户的实际表现:
    在其他银行的还款记录良好
    违约率仅2.3%，低于整体平均的3.8%
  
[运营建议]
  1. 将上诉模式加入"人工复核推荐通过"名单（优先级P1）
  2. 调整筛选规则对短期限贷款的权重
  3. 预期可召回每月XX万元的优质贷款
```

#### 场景3: 审批流程异常检测

```
[探索智能体发现]
  有5笔申请的`affects`链不完整（跳过BFT/价值核定）
  这5笔的最终不良率: 20%（vs平均3.8%）
  
[SHACL验证]
  :CompletePathShape 约束被违反
  
[运营建议]
  1. 标记这5笔为"高优先级审查"（优先级P0）
  2. 检查相关审批人员的操作权限
  3. 在系统中强制`affects`链的完整遍历
```
