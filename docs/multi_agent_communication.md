# 多 GenericAgent 通讯机制

> 基于 GenericAgent 系统的多层智能体协作架构
> 创建日期：2026-05-08

---

## 概述

GenericAgent 支持多智能体协作，核心通讯模式是基于**文件系统的异步 IO 协议 + 共享记忆**。当前已实现四种通讯模式：主从模式、Map并行模式、监察者模式、隐式共享记忆模式。

---

## 第一层：主从模式（Master-Subagent）

最成熟的通讯机制，主 Agent 与 Subagent 之间通过 **文件系统 IO 协议** 通讯：

```
┌─────────────────┐         文件系统          ┌─────────────────┐
│   主 Agent       │ ◄──────────────────────► │   Subagent       │
│  (你当前的角色)   │    temp/{task_name}/      │  (工作智能体)     │
└─────────────────┘                          └─────────────────┘
```

### 通讯通道（6种文件）

| 文件 | 方向 | 用途 |
|------|------|------|
| `input.txt` | 主→Sub | 任务目标与约束（**只给目标，不写步骤**） |
| `context.json` | 主→Sub | 绝对路径、交付物清单、依赖关系 |
| `output.txt` | Sub→主 | 执行过程输出（append，`[ROUND END]` 标记轮次） |
| `reply.txt` | 主→Sub | 对 subagent 提问的回复，继续对话 |
| `_intervene` | 主→Sub | 纠偏指令（跳步、遗漏、断言无据等） |
| `_keyinfo` | 主→Sub | 注入 working memory（提前塞入关键信息） |
| `_stop` | 主→Sub | 终止信号（当轮结束后退出） |

### 启动方式

```powershell
# 前台运行
python agentmain.py --task my_task --input "完成XX任务"

# 后台运行（推荐）
python agentmain.py --task my_task --input "..." --bg
# 输出 PID，主agent可轮询 output.txt
```

### 关键约束

- Subagent 的 cwd 与主 Agent 相同（都是 `temp/`）
- **主 Agent 空闲时应读 output 观察进度，必要时用干预文件纠偏**
- **禁止无脑长时间 sleep 轮询**
- Subagent 同样具备完整智能，内部可创建自己的 plan_mode

### 干预文件详解

| 文件 | 写入时机 | 效果 |
|------|---------|------|
| `_stop` | 任务需终止时 | Subagent 当轮结束后退出 |
| `_keyinfo` | 即将进入中后期步骤前 | 提前注入该步骤的关键细节到 working memory |
| `_intervene` | 发现偏差时 | 追加指令，纠正行为（如"你跳过了 StepN，先做"） |

## 第二层：Map 模式（并行分发）

当有 N 个独立同构子任务时，一对多通讯：

```
┌─────────────┐
│  主 Agent    │
└──────┬──────┘
       │ 分发 input1.txt / input2.txt / input3.txt
       │
┌──────┴──────┐
│ 🧠 Sub 1    │─── 处理文件A ──→ output1.txt
│ 🧠 Sub 2    │─── 处理文件B ──→ output2.txt
│ 🧠 Sub 3    │─── 处理文件C ──→ output3.txt
└─────────────┘
       │ 收集
       ▼
┌─────────────┐
│  主 Agent    │ ←── 读所有 output*.txt，汇总结果
└─────────────┘
```

### 适用条件

- 任务可拆分为**独立同构**的子任务
- 子任务之间的上下文**互不依赖**
- 每个子任务处理的是**不同的输入文件**

### 标准流程（Map-Reduce）

1. **主 Agent 准备阶段**：爬取/收集数据，存为多个独立输入文件
2. **分发阶段**：对每个文件启动一个 Subagent 处理（主 Agent 自己也可以处理其中一个）
3. **收集阶段**：等所有 Subagent 完成，主 Agent 读取各输出文件，汇总结果

### 优势与局限

| 维度 | 说明 |
|------|------|
| ✅ 优势 | 独立上下文，避免长文档互相污染 |
| ✅ 优势 | 可并行执行，提高吞吐量 |
| ⚠️ 局限 | 共享资源冲突：键鼠不可共享 |
| ⚠️ 局限 | 浏览器暂时不可并行使用（避免同时操作同一标签页） |

## 第三层：监察者模式（Supervisor-Worker）

三 Agent 协作的最高形式：

```
┌──────────────┐
│  监察者       │ ← 只读、只判断、只干预，不干活
│  (Supervisor) │
└──────┬───────┘
       │ 读 output.txt（观察进度）
       │ 写 _intervene / _keyinfo（纠偏）
       │
       ▼
┌──────────────┐         ┌──────────────┐
│  工作 Agent   │         │  验证 Agent   │ (可选)
│  (Worker)    │         │  (Verifier)  │
└──────────────┘         └──────────────┘
```

### 监察者红线

- **禁止下场干活**：不操作浏览器、不写代码、不执行任务步骤。只读、只判断、只干预
- **可以读环境**：`file_read` / `web_scan` / `web_execute_js` / `code_run`（只读命令）获取情报

### 监察者干预清单

| 发现 | 干预方式 |
|------|---------|
| 跳步 | `_intervene`：你跳过了 StepN，先做 |
| 细节遗漏 | `_intervene`：你漏了 XX 约束，重做/补上 |
| 光说不做 | `_intervene`：别说了，直接做 |
| 断言无据 | `_intervene`：你怎么确认的？验证一下 |
| 连续失败 | `_intervene`：停，先读错误日志再决定 |
| 感觉要偏 | `_intervene`：去重读 SOP 的 StepN 再继续 |
| 即将进入中后期步骤 | `_keyinfo`：提前注入该步骤的⚠️细节 |

### 干预原则

- **沉默为主**：没问题不说话
- **一句话**：像用户一样直接说，禁长篇解释
- **`_keyinfo` 只用于提前预注入**：在工作 Agent 到达该步之前塞细节。已经犯错的一律用 `_intervene` 纠正

## 第四层：共享记忆机制（隐式通讯）

所有 Agent **共享同一套记忆系统**，这是最基础的隐式通讯：

```
┌────────────────────────────────────────┐
│          shared memory                 │
│  ┌────────┐ ┌────────┐ ┌──────────┐   │
│  │ L1     │ │ L2     │ │ L3 SOP   │   │
│  │Insight │ │ Fact   │ │ /utils   │   │
│  └────────┘ └────────┘ └──────────┘   │
│  ┌────────────────────────────────┐   │
│  │ keychain（共享密钥）            │   │
│  └────────────────────────────────┘   │
│  ┌────────────────────────────────┐   │
│  │ 文件系统（共享工作区）          │   │
│  └────────────────────────────────┘   │
└────────────────────────────────────────┘
           ↕            ↕
       ┌──────┐   ┌──────┐
       │Agent1│   │Agent2│
       └──────┘   └──────┘
```

### 隐式通讯通道

| 媒介 | 通讯方式 | 时效性 |
|------|---------|--------|
| L1 Insight | 任何 Agent 写入的规则，其他 Agent 启动时自动注入 | 跨会话 |
| L2 global_mem.txt | 环境事实共享 | 跨会话 |
| L3 SOP / utils | 可复用流程与工具，所有 Agent 可调用 | 跨会话 |
| keychain | 加密密钥共享（如 Metaso API Key） | 持久化 |
| 文件系统 | 通过文件传递数据和结果 | 实时 |

## 完整的多 Agent 协同示例

以"分析并修复代码"的任务为例：

```
                    ┌──────────────┐
                    │  用户需求     │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │  主 Agent     │ ← 制定计划，分派任务
                    │  (Orchestrator)
                    └──────┬───────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
    ┌─────▼──────┐  ┌─────▼──────┐  ┌─────▼──────┐
    │ 工作 Agent 1│  │ 工作 Agent 2│  │ 监察者     │
    │ 分析代码    │  │ 搜索资料    │  │ (Supervisor)│
    └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
          │ output.txt     │ output.txt     │
          └────────┬───────┘               │
                   │                       │
                   ▼                       │
            ┌──────────┐                  │
            │主Agent汇总│ ◄────────────────┘
            │结果+验证  │ 读output判断进度
            └─────┬────┘
                  │
                  ▼
            ┌──────────┐
            │验证Agent  │ ← 对抗性验证交付物
            │(Verifier)│
            └──────────┘
```

### 各 Agent 职责

| 角色 | 职责 | 通讯方式 |
|------|------|---------|
| 主 Agent (Orchestrator) | 拆解任务、分派、汇总 | 创建 input.txt + context.json |
| 工作 Agent (Worker) | 执行具体任务步骤 | 写入 output.txt |
| 监察者 (Supervisor) | 监控进度、纠偏 | 读取 output.txt，写入干预文件 |
| 验证 Agent (Verifier) | 对抗性验证交付物质量 | 读取交付物，输出 VERDICT |

## 当前能力的局限与可改进方向

| 短板 | 说明 | 可能改进方向 |
|------|------|-------------|
| **无实时 RPC** | 全走文件系统，有 IO 延迟 | 添加 socket / 命名管道通道 |
| **无广播机制** | 只能点对点，无法一对多通知 | 添加消息队列（如 Redis / NATS） |
| **无心跳检测** | 无法判断 subagent 是否存活 | 添加 PID 存活性检查 + 超时机制 |
| **浏览器互斥** | 多个 Agent 不能同时操作浏览器 | 添加浏览器实例隔离或锁机制 |
| **无自动发现** | 新 Agent 不会主动注册自己 | 添加注册中心或服务发现 |

---

## 总结

| 维度 | 当前能力 | 通讯媒介 |
|------|---------|---------|
| 主→Sub | ✅ 文件 IO 协议（input/reply/intervene） | `temp/{task}/` 目录 |
| Sub→主 | ✅ 追加写 output.txt | `temp/{task}/output.txt` |
| 并行 Map | ✅ 多 Subagent 独立处理 | 不同 `{task}/input*` 文件 |
| 监察干预 | ✅ Supervisor 读写干预文件 | `_intervene`, `_keyinfo` |
| 记忆共享 | ✅ 全局记忆系统 | `memory/` 目录 + keychain |
| 跨进程通信 | ⚠️ 仅有文件系统，无 RPC | 可扩充 socket / named pipe |
| 自动注册 | ❌ 无 | 可增加注册机制 |

核心设计哲学：**用最简单的文件系统实现最灵活的 Agent 协作**，避免引入复杂的外部依赖。当需要更实时的通讯时，可在现有架构上扩展 socket 或消息队列通道。
