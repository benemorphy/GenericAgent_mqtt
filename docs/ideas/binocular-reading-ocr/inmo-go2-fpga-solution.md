# INMO GO 2 + Supervision (FPGA硬件化) 方案

> 多Agent头脑风暴产出 | 2026-06-09
> 基于影目INMO GO 2 AI眼镜 + Roboflow Supervision视觉库 + FPGA硬件加速的专用阅读OCR方案

---

## 方案定位

在原 vision-v1.md 的三条演进路线中，这是 **Phase 3 (眼镜独立运行)** 的具体实现：

```
Phase 1: 桌面支架PC (算法验证)
Phase 2: 手机+AI眼镜 (移动化)
Phase 3: INMO GO 2 + FPGA (眼镜独立, 本方案)
```

**核心思路**: 将 Supervision 的视觉管线关键环节 FPGA 化，集成到 INMO GO 2 眼镜中，实现脱离手机的独立阅读OCR设备。

---

## 发散阶段：5个Agent视角

### Agent 1 — FPGA 架构师

**关注点**: 如何将 Supervision 视觉管线映射到 FPGA 硬件逻辑

| 想法 | 说明 |
|------|------|
| F1. 立体匹配硬件化 | SGM/Semi-Global Matching 算法适合FPGA流水线, 双目视差图可做到 <5ms/帧, 功耗 <200mW |
| F2. YOLO推理加速器 | 将 YOLOv11n 的卷积层映射到 FPGA DSP单元, INT8量化, 推理 <10ms/帧, 功耗 <500mW |
| F3. 柱面展平IP核 | 双线性插值的坐标变换映射到FPGA管线, 支持1920x1080实时输出, 延迟 <1ms |
| F4. 图像预处理流水线 | 去噪/直方图均衡/自适应阈值全部硬件化, 不占CPU |
| F5. Supervision Detections 硬件桥接 | FPGA输出结果直接映射为 sv.Detections 格式的共享内存结构, 无需软件序列化 |

**收敛**: F1+F2+F3 组合为 **三芯合一** FPGA加速单元

### Agent 2 — AI眼镜嵌入式专家

**关注点**: INMO GO 2 平台特性与 FPGA 集成方式

| 想法 | 说明 |
|------|------|
| H1. 眼镜骨架改造 | INMO GO 2 镜腿中空设计, FPGA模块可嵌入镜腿末端(平衡配重) |
| H2. MIPI CSI直连 | FPGA直接接双目传感器(绕过眼镜SoC), 减少延迟 |
| H3. FPGA + SoC 双芯片架构 | FPGA做视觉前端, INMO GO 2的SoC做应用层(SQLite-vss/网络), USB 3.0互联 |
| H4. 外挂FPGA计算模块 | 眼镜通过USB-C外挂FPGA加速棒(类似RayNeo X2外挂方案), 不增加眼镜重量 |
| H5. eDP直驱光波导 | FPGA处理完图像后直接驱动光波导显示(叠加OCR结果), 绕过主SoC渲染管线 |

**收敛**: **H3 + H4 双模架构** — 默认外挂FPGA模块(减重), 未来集成到镜腿

### Agent 3 — 计算机视觉算法专家

**关注点**: Supervision 管线中哪些部分可 FPGA 化

| 想法 | 说明 |
|------|------|
| A1. sv.Detections 推理加速 | YOLO前处理(NMS/置信度过滤) FPGA化, 减少CPU负载 |
| A2. sv.ByteTrack 协处理 | 卡尔曼滤波/IOU计算的硬件卸载, 但软件追踪灵活度更高, 保持CPU |
| A3. sv.Annotators 渲染加速 | 文本/标注渲染放到FPGA, 直接合成到光波导显示 |
| A4. 柱面展平 FPGA化 | 关键路径: 双目->视差->3D点->展平, 全FPGA流水线 <20ms |
| A5. OCR加速 | PaddleOCR的检测+识别模型FPGA化(需大容量FPGA) |

**收敛**: A1 + A4 是最大收益点; A5(OCR)保持SoC运行(灵活性更重要)

### Agent 4 — 系统功耗/散热专家

**关注点**: FPGA 功耗与眼镜形态的物理约束

| 想法 | 说明 |
|------|------|
| P1. FPGA选型 | **Lattice CrossLink-NX** (28nm, <1W) 适合双目MIPI接入+预处理; **Xilinx Artix-7** (28nm, 2-3W) 适合YOLO推理 |
| P2. 功耗预算分配 | 双目传感器 ~500mW + FPGA ~1500mW + SoC ~1000mW = 3000mW, 眼镜电池(800mAh)续航 ~15分钟 |
| P3. 外挂电池方案 | 眼镜本体轻薄(电池400mAh), 外挂领夹电池(3000mAh)提供续航 ~2小时 |
| P4. 动态功耗调节 | 静坐阅读时全速运行; 放下眼镜时待机(<100mW); 翻页检测用低功耗传感器唤醒 |
| P5. 散热方案 | FPGA位于镜腿末端(远离皮肤), 铝散热片嵌入镜腿外壳, 被动散热足够 |

**收敛**: 外挂电池方案(P3) + 动态功耗调节(P4) 使续航达到可用水平

### Agent 5 — 产品化专家

**关注点**: 从原型到产品, 市场定位

| 想法 | 说明 |
|------|------|
| M1. 对标产品定位 | 差异化于Meta Ray-Ban (社交/拍照) 和 Rokid (观影), 定位**知识工作者工具** |
| M2. MVP验证路径 | Step 1: 手机+INMO GO 2+PC处理(验证管线) → Step 2: FPGA外挂模块(验证加速) |
| M3. 开源+社区策略 | Supervision开源生态 > 自有协议, 回馈开源社区建立品牌 |
| M4. B端 > C端先发 | 先做律所/研究院/高校的批量采购(知识库刚需), 后做个人消费品 |
| M5. 隐私卖点 | FPGA本地推理 + 离线可用 + 数据不出设备 = 企业级隐私合规 |

**收敛**: M2(分步验证) + M4(B端先行) 作为产品路线

### 数据流

```
帧触发(ToF) → 双目传感器 → MIPI CSI
    ↓
FPGA 立体匹配 → 视差图 → 3D点云
    ↓
FPGA 柱面展平 → 矫正后平面图
    ↓
FPGA YOLOv11n → sv.Detections 格式
    ↓ (共享内存)
SoC PaddleOCR → 文本
    ↓
SoC SQLite-vss → 向量入库
    ↓
FPGA 标注渲染 → 光波导显示 (OCR结果叠加在视野中)
    ↓
Wi-Fi 后台同步 → 云端/PC知识库
```

## 关键技术决策

| 决策 | 选项 | 推荐 | 理由 |
|------|------|------|------|
| FPGA型号 | Lattice CrossLink-NX vs Xilinx Artix-7 | **Lattice CrossLink-NX-40** | 原生MIPI CSI输入, <1W, 适合眼镜 |
| FPGA-Mem接口 | 共享DDR vs 独立DDR | **独立DDR4(FPGA) + LPDDR4(SoC)** | 避免总线竞争, 各自最优 |
| 互联总线 | USB 3.0 vs PCIe 2x | **USB 3.0 OTG** | INMO GO 2已有USB-C, 无需改硬件 |
| YOLO量化 | INT8 vs FP16 | **INT8** | Lattice NPU原生支持, 精度损失<2% |
| OCR引擎 | PaddleOCR vs 自研 | **PaddleOCR Lite** | 成熟, 支持SoC NPU加速 |
| 知识库同步 | 实时Wi-Fi vs 离线积累后同步 | **离线积累+Wi-Fi批量同步** | 阅读时不耗电, 充电时同步 |

## FPGA 资源估算

| 模块 | LUT | DSP | BRAM | 功耗 | 延迟 |
|------|-----|-----|------|------|------|
| 立体匹配(SGM) | 28k | 64 | 128 | 180mW | 3-5ms |
| 柱面展平(双线性) | 12k | 32 | 64 | 80mW | <1ms |
| YOLOv11n(INT8) | 65k | 256 | 256 | 450mW | 6-8ms |
| 图像预处理 | 8k | 16 | 32 | 40mW | <0.5ms |
| sv.Detections桥接 | 2k | 0 | 8 | 10mW | 无延迟 |
| **总计** | **115k** | **368** | **488** | **~760mW** | **<15ms/帧** |

**推荐FPGA**: Lattice CrossLink-NX-40 (39k LUT, 160 DSP, 192 BRAM) **不足以容纳全部逻辑**

**替代方案**: 分层部署
- 小FPGA (CrossLink-NX-40, 40k LUT): 立体匹配 + 柱面展平
- 大FPGA (CrossLink-NX-100, 99k LUT): YOLO推理
- 或者: Xilinx Artix-7 200T (134k LUT, 740 DSP) 单片搞定

```

  用已有双目相机(RealSense D435i) + PC

  [比桌面更真实的阅读体验]

  FPGA跑立体匹配+柱面展平, PC跑YOLO+OCR

  修改INMO GO 2镜腿嵌入FPGA
  双芯片共板, 一体化散热
  [量产原型]
```

## 总结

本方案的核心竞争力在于 **Supervision + FPGA 硬件化**:

1. **Supervision 提供模型生态**: YOLO 页面检测模型 + ByteTrack 追踪器, 无需自研视觉算法
2. **FPGA 提供实时性**: 双目立体匹配 + 柱面展平 + YOLO推理 <15ms/帧, 满足翻页实时采集
3. **INMO GO 2 提供穿戴着**: 双目RGB + Android SoC + 光波导显示, 成熟的可穿戴平台
4. **外挂模块策略**: 不拆眼镜即可验证FPGA价值, 降低产品化风险

**一句话**: 将 Supervision 的视觉能力通过 FPGA 硬件化塞进 INMO GO 2 眼镜, 实现独立运行的阅读OCR一体机。

### FPGA与SoC互联方案

| 方案 | 带宽 | 延迟 | 功耗 | 复杂度 | 适用阶段 |
