# 双目阅读OCR一体

> 多Agent头脑风暴产出 | 2026-06-09

## 核心理念

使用双目相机获取书本图像 -> 三维重建当前页面曲面 -> 展平曲面 -> OCR读入 -> 后台知识库同步收集OCR信息。读者阅读时，同步完成知识库更新。

---

## 发散阶段：5个Agent视角

### Agent 1 — 计算机视觉专家

**关注点**: 双目成像 + 曲面重建 + 展平

| 想法 | 说明 |
|------|------|
| V1. 实时曲面网格重建 | 双目视差图 -> 稠密深度图 -> 三角网格 -> 每帧增量更新, 响应 < 30ms |
| V2. 书脊中线检测 + 柱面模型 | 简化模型: 检测页面中脊线, 假设页面为圆柱面, 只需2个参数(曲率半径+倾斜角)即可重建 |
| V3. 光流辅助跟踪 | 翻页时用光流跟踪页面轮廓, 避免全帧重算, 降低功耗 |
| V4. 页面边缘检测+单应校正 | 轻量方案: 检测页面四边形边界 -> 透视变换 -> 不依赖深度, 速度最快但展开精度最低 |
| V5. 混合方案: 柱面近似 + 局部微调 | 先用柱面模型粗展开, 再用局部纹理畸变校正精调, 平衡精度和速度 |

### Agent 2 — OCR/NLP 专家

**关注点**: 文字识别 + 版面分析 + 语义后处理

| 想法 | 说明 |
|------|------|
| O1. 端到端版面识别 | 用 LayoutLM / PaddleOCR 直接识别展平后的图像, 保持段落/标题/列表结构 |
| O2. 增量OCR: 只读变化区域 | 利用双目跟踪结果, 只OCR页面新增/变化区域, 避免重复识别 |
| O3. 语义去重 | 同一段文字可能被连续帧重复识别 -> 用文本指纹(SimHash)去重, 只保留新内容 |
| O4. 数学公式/图表识别 | 集成 LaTeX OCR + 图表描述模型, 不只读文字 |
| O5. 阅读进度追踪 | 根据双目视线估计 + 当前OCR内容, 定位读者读到了哪一行, 标注入库位置 |

### Agent 3 — 知识库架构师

**关注点**: 数据结构 + 同步策略 + 查询

| 想法 | 说明 |
|------|------|
| K1. 增量向量化流水线 | OCR文本 -> Chunk -> Embedding -> Upsert to Vector DB, 端到端延迟 < 1s |
| K2. 层级知识结构 | 书->章->节->段落 四级结构, 保留上下文parent指针, 支持溯源 |
| K3. 阅读态标记 | 每个条目标记: unread / reading / read / annotated, 与阅读进度联动 |
| K4. 双向链接 | OCR提取的实体/引用自动建链: 脚注链接到原文, 术语链接到术语表 |
| K5. 离线优先同步 | 本地SQLite暂存, 有网时同步到远端, 支持多设备阅读进度合并 |

### Agent 4 — 硬件/IoT 工程师

**关注点**: 设备形态 + 功耗 + 散热

| 想法 | 说明 |
|------|------|
| H1. 头戴式双目方案 | 类似Google Glass形态, 双目朝下看书的姿势, 内置IMU自动激活 |
| H2. 桌面支架方案 | 固定角度双目摄像头对准桌面, 配合补光灯, 适合长时间阅读, 散热好 |
| H3. 手机夹持方案 | 手机+外接双目镜头配件, 利用手机算力, 低成本 |
| H4. 专用阅读灯一体 | 阅读灯内嵌双目摄像头 + LED补光, 用户不觉有摄像头存在 |
| H5. 按键触发 vs 自动触发 | 手动按键拍照 vs 自动检测翻页动作触发, 功耗差10x |

### Agent 5 — 产品/UX 设计师

**关注点**: 用户体验 + 场景 + 隐私

| 想法 | 说明 |
|------|------|
| P1. 零操作阅读 | 戴上即用, 无任何操作, 翻页自动拍, 读完合书自动停 |
| P2. 实时预览层 | AR眼镜上显示OCR实时结果和知识库标注, 不干扰阅读视线 |
| P3. 隐私模式 | 只处理书页区域, 人脸/环境不录入, 处理结果本地优先, 可选加密同步 |
| P4. 阅读仪表盘 | 周阅读量/知识库新增量/关联发现数, 形成知识增长曲线 |
| P5. 协作批注 | 多读者在同一本书上做批注, 知识库自动聚合, 形成群体智能 |

## 关键技术决策

| 决策 | 选项 | 推荐 | 理由 |
|------|------|------|------|
| 展平算法 | 柱面模型 vs 网格重建 | **柱面模型(V5)** | 足够精度, <10ms/帧 |
| OCR引擎 | PaddleOCR vs Tesseract vs 云API | **PaddleOCR(本地)** | 中文好, 本地推理, 隐私友好 |
| 向量存储 | SQLite-vss vs Chroma vs Milvus | **SQLite-vss(本地)** | 零部署, 离线可用 |
| Embedding | BGE vs text-embedding-3-small | **BGE-small(本地)** | 本地运行, 速度快 |
| 硬件方案 | 头戴 vs 桌面支架 | **桌面支架(H2)** | 先MVP, 散热好, 开发成本低 |

## 最小可行版本(MVP)步骤

1. **Step 1**: 用现有双目摄像头 + 电脑, 实现柱面展平 + PaddleOCR, 命令行输出文本
2. **Step 2**: 加入 SQLite-vss 向量存储, 增量入库, 简单Web界面查看知识库
3. **Step 3**: 桌面支架硬件定型, 自动触发翻页检测, 实现零操作阅读
4. **Step 4**: 阅读仪表盘 + 隐私模式 + 层级知识结构

## 效果

读者阅读时，同步完成知识库更新。无需任何额外操作，翻页即采集，采集即入库，入库即可查。

## 硬件专题

### 光流跟踪是硬件实现吗？

**不一定，取决于平台。**

| 实现方式 | 说明 | 功耗 | 精度 | 适用阶段 |
|----------|------|------|------|----------|
| **纯软件 OpenCV** (calcOpticalFlowFarneback / DIS) | CPU上运行, 无需专用硬件 | 中 | 中 | 开发原型 |
| **GPU光流** (NVIDIA NVOF / RAFT深度学习模型) | GPU加速, 高精度 | 高 | 高 | 桌面MVP |
| **硬件光流引擎** (NVIDIA Jetson NVOF引擎) | 专用硬件单元, 不占GPU/CUDA | 极低 | 中高 | 嵌入式产品 |

**本方案推荐**: 开发阶段用 **OpenCV DIS光流**(软件), 产品化后用 **Jetson NVOF硬件引擎**(降低功耗)。

### 双目相机推荐

| 型号 | 类型 | 分辨率 | 帧率 | 基线 | 接口 | 适合原因 |
|------|------|--------|------|------|------|----------|
| **Intel RealSense D435i** | 主动双目+IR | 1280x720 | 90fps | 50mm | USB 3.0 | 全局快门, 室内近距离(<1m)最佳, 有IMU |
| **Intel RealSense D455** | 主动双目+IR | 1280x720 | 90fps | 95mm | USB 3.0 | 基线更长, 深度精度更高, 适合A4幅面 |
| **StereoLabs ZED 2** | 被动双目 | 2208x1242 | 15fps | 120mm | USB 3.0 | 分辨率高, 户外也ok, 但帧率低 |
| **USB双目模组(无品牌)** | 被动双目 | 1280x480(拼接) | 30fps | 40-80mm | USB 2.0 | 成本低(~200元), 需手动标定 |
| **OAK-D Pro** (Luxonis) | 双目+AI加速 | 1280x800 | 60fps | 75mm | USB 3.0 | 板载AI推理, 可本地跑光流 |

**MVP推荐**: Intel RealSense D435i + USB 3.0 直连PC。理由:
- 出厂已标定, 开箱即用, 无需手动做立体标定
- 全局快门: 翻页运动模糊少
- IMU辅助: 可以检测阅读姿态变化
- 主动IR: 暗光下仍可工作

### 计算平台推荐

| 平台 | 处理器 | 光流加速 | OCR加速 | 接口要求 | 功耗 | 适合阶段 |
|------|--------|----------|---------|----------|------|----------|
| **普通PC (i5+/NVIDIA GPU)** | x86 | GPU(CUDA) | GPU(CUDA) | USB 3.0 x1 | ~200W | 开发原型 |
| **Jetson Orin Nano** | ARM Cortex-A78 + Ampere GPU | NVOF硬件引擎 | GPU(CUDA) | USB 3.0 + CSI | 7-15W | 嵌入式产品 |
| **Jetson Orin NX** | ARM + Ampere GPU | NVOF硬件引擎 | GPU(CUDA) | USB 3.0 + CSI | 10-25W | 高性能产品 |
| **树莓派 5** | ARM Cortex-A76 | CPU软件 | CPU(慢) | USB 3.0 | 5W | 低配验证 |

**MVP推荐**: 普通PC + NVIDIA GPU（开发阶段）。产品化后迁移到 **Jetson Orin Nano**(15W模块)。

| 硬件 | 推荐型号 | 用途 |

### 硬件接口总览

```
双目相机 (Intel RealSense D435i)
  └─ USB 3.0 Type-C → 主机USB 3.0 (5Gbps, 供电+数据)

LED补光灯
  └─ USB 2.0 Type-A → 主机USB 2.0 (5V供电)

ToF翻页传感器 (VL53L1X)
  └─ I2C (通过 Arduino/ESP32) → USB-UART → 主机USB 2.0

脚踏开关
  └─ USB HID → 主机USB 2.0 (即插即用, 无驱动)

电源:
  └─ 双目相机: USB总线供电 (4.5W)
  └─ LED补光灯: USB总线供电 (2.5W)
  └─ 传感器: USB总线供电 (0.1W)

总计: 需要 2x USB 3.0 + 2x USB 2.0 端口
  (或使用 USB HUB 扩展)
```

### 备选: 纯手机方案(最低成本)

如果不想购置双目相机, 可以用 **一台手机 + ChatGPT API** 做概念验证(PoC):
1. 手机支架固定, 摄像头对准书本
2. 每翻一页拍照(手动触发)
3. 用 ChatGPT Vision API 做 OCR + 结构化
4. 手动粘贴到知识库

成本 ~0元(硬件已有), 但无法实现自动化和实时性。适合先验证"阅读同步知识库"的流程价值。


### 方案三: 手机 + AI 眼镜(双目)

利用已有智能手机做主控 + AI 眼镜(自带双目摄像头)作为感知前端，无需额外购置双目相机。

#### AI 眼镜选型

| 型号 | 双目方案 | 分辨率 | 帧率 | 接口 | 重量 | 参考价 | 特点 |
|------|----------|--------|------|------|------|--------|------|
| **Meta Ray-Ban (v2/v3)** | 单目(右) + 深度传感器 | 3024x3024 | 30fps | 蓝牙/WiFi/App | ~50g | ~3000元 | 生态完善, 拍照触发App回调 |
| **Rokid Glasses** | 双目 RGB | 640x480 | 60fps | USB-C / WiFi | ~75g | ~2000元 | 开放SDK, 可自定义图像处理管线 |
| **影目 INMO GO 2** | 双目 RGB | 1280x720 | 30fps | Wi-Fi / 蓝牙 | ~90g | ~2500元 | Android系统, 可侧载App |
| **INMO Air 2** | 双目 RGB | 640x480 | 30fps | 有线直连手机 | ~80g | ~2000元 | 眼镜端可做轻量预处理 |
| **雷鸟X2** | 双目+光波导 | 2560x1440 | 30fps | USB-C DP | ~85g | ~2800元 | 高分辨率, 色彩还原好 |

**推荐**: **Rokid Glasses** 或 **INMO Air 2**。理由:

- 开放SDK, 可将双目图像实时推送到手机
- 重量轻(75-80g), 长时间佩戴可行

#### 手机端处理管线

```
AI 眼镜  (双目图像采集)
    │ Wi-Fi / USB-C
    ▼
智能手机 (计算核心)
    ├─ 双目视差 → 柱面模型展平 (CPU/GPU)
    ├─ PaddleOCR Lite (NPU/GPU)
    └─ SQLite-vss 向量入库 (CPU)
    │
    ▼
知识库 (手机本地)
```

#### 硬件接口

```
AI 眼镜 → 手机:

USB-C 直连模式:
  ─ 眼镜 USB-C ←→ 手机 USB-C (OTG)
  ─ 供电: 手机供电 (5V/1A)
  ─ 数据: UVC协议视频流 (双目, ~30MB/s)
  ─ 延迟: <50ms

Wi-Fi 无线模式:
  ─ 眼镜作为热点或同一局域网
  ─ 数据: MJPEG压缩流 (单目, ~5MB/s)
  ─ 延迟: 100-200ms (无线, 适合翻页后采集)

推荐: USB-C 直连 → 低延迟、稳定
```

#### 手机端软件栈

| 层级 | 方案 | 说明 |
|------|------|------|
| 双目驱动 | 手机端集成UVC驱动 + OpenCV | 眼镜推流, 手机端接收立体帧 |
| 曲面重建 | OpenCV + 柱面模型 | 与PC版算法一致, 手机CPU可跑 |
| OCR | PaddleOCR Lite (NNAccel) | 利用手机NPU/GPU加速 |
| 向量库 | SQLite-vss + BGE-M3 | 手机端离线可用 |
| 触发检测 | 手机加速度计 + 眼镜陀螺仪 | 检测低头/抬头判断翻页 |

#### 与桌面支架方案对比

| 维度 | 桌面支架方案 | 手机+AI眼镜方案 |
|------|-------------|-----------------|
| **形态** | 固定桌面, 书本放于相机下 | 可移动, 随时随地阅读 |
| **成本(增量)** | ~2180元 | ~2000-3000元(眼镜) |
| **需额外设备** | 双目相机+PC+支架 | AI眼镜+已有手机 |
| **实时性** | 高 (PC GPU) | 中 (手机NPU) |
| **隐私性** | 固定位置, 不易泄露 | 移动场景, 需注意周围隐私 |
| **续航** | 插电无限 | 手机+眼镜 ~3-4小时 |
| **适合场景** | 书房/办公桌 | 通勤/咖啡厅/图书馆 |

#### 推荐演进路线

```
Phase 1: 桌面支架PC方案 (验证算法)
     ↓
Phase 2: 手机+AI眼镜 (移动化、产品化)
     ↓
Phase 3: AI眼镜独立运行 (SoC集成, 脱离手机)
```

**手机+AI眼镜方案是本项目从桌面原型走向便携产品的关键第二步。**

## 与 Supervision 集成分析

> [Supervision](https://github.com/roboflow/supervision) (43k stars) — 模型无关的计算机视觉工具包, 提供检测、追踪、标注、可视化等基础组件。

### Supervision 与本方案管线对照

| 管线阶段 | 本方案需求 | Supervision 能力 | 结合价值 |
|----------|-----------|-----------------|----------|
| 页面检测 | 双目图像中检测书本/页面边界 | `sv.Detections` + YOLO/RTDETR 模型 | 快速集成页面检测模型, 无需自研 |
| 页面角点追踪 | 翻页时跟踪4个角点位置 | `sv.ByteTrack` 多目标追踪 | 替代光流, 更轻量、更鲁棒 |
| 曲面重建可视化 | 绘制重建网格调试 | `sv.BoxAnnotator` / `sv.MaskAnnotator` | 直观调试展平效果 |
| OCR结果可视化 | 在原始图像上绘制OCR文本 | `sv.LabelAnnotator` / `sv.TextAnnotator` | 可视化OCR覆盖效果 |
| 训练数据准备 | 训练页面检测模型所需数据集 | `sv.DetectionDataset` (COCO/YOLO/Pascal) | 一键格式转换, 无需手写转换脚本 |

### 具体集成点

#### 集成点1: 页面区域检测 (替代或辅助柱面模型)

```python
import supervision as sv
from ultralytics import YOLO

# 加载预训练页面检测模型 (或用Roboflow训练定制模型)
model = YOLO("page_detector.pt")  # 或在Roboflow上训练

# 双目左图检测页面边界
results = model(left_image)
detections = sv.Detections.from_ultralytics(results[0])

# 提取页面4个角点 (由检测框提供初始位置)
page_box = detections.xyxy[0]  # [x1, y1, x2, y2]

# Supervision提供角点作为柱面重建的初始参数
# 替代: 手动角点检测 + 光流跟踪
```

**收益**: 从「纯几何角点检测 + 光流」 → **检测 + 追踪**, 更鲁棒。光照变化、部分遮挡下仍能工作。

#### 集成点2: 页面追踪 (替代光流)

```python
import supervision as sv

# 初始化BYTETracker
tracker = sv.ByteTrack()

# 每帧检测页面 → 追踪ID保持不变
detections = sv.Detections(...)  # 来自YOLO或角点检测
tracked = tracker.update_with_detections(detections)

# 追踪到同一页面ID → 平滑相邻帧参数
# 无需每帧重跑立体匹配, 只需更新追踪框
```

**收益**: 
- 替代光流跟踪（本方案V7提出翻页光流跟踪）
- BYTETracker 仅需检测框, 计算量 < 1ms/帧
- 翻页时检测框断掉 → 重新检测 → 新ID, 可触发OCR采集

### 集成后管线对比

**原管线**:
```
双目帧 → 特征点匹配 → 视差图 → 柱面参数 → 展平 → OCR
    └── 光流跟踪 (每帧重算)
```

**集成 Supervision 管线**:
```
双目帧 → YOLO页面检测 → sv.Detections → 柱面参数 → 展平 → OCR
              └─ sv.ByteTrack (跨帧追踪, <1ms)
              └─ sv.Annotators (调试可视化)
              └─ sv.DetectionDataset (训练数据)
```

### 建议优先级

| 集成点 | 阶段 | 工作量 | 收益 |
|--------|------|--------|------|
| **页面检测 + ByteTrack 追踪** | MVP之后 | 小(已有YOLO模型) | 大(替代光流) |
| **可视化调试 (Annotators)** | 开发过程中 | 极小(几行代码) | 大(加速调试) |
| **训练数据管线** | 需定制模型时 | 中(标注数据) | 大(自主模型) |

### 关键技术决策

| 决策 | 选项 | 推荐 |
|------|------|------|
| 页面检测模型 | YOLOv11 vs RTDETR vs 自训练 | **YOLOv11n**(轻量, 手机可跑) |
| 追踪器 | ByteTrack vs BoT-SORT | **ByteTrack**(Supervision内置, 够用) |
| 训练数据来源 | Roboflow公开数据集 vs 自采 | **先Roboflow预训练模型, 再微调** |
| 集成方式 | 直接pip install supervision | 无额外依赖, 零部署成本 |

### 总结

Supervision 不是本方案的**必须依赖**, 但它能:
1. **简化代码**: 用 `sv.ByteTrack` 替代手写光流追踪器
2. **加速原型**: 用预训练 YOLO 模型 + `sv.Detections` 快速得到页面边界
3. **提供数据管线**: 训练自定义页面检测模型的完整工具链
4. **可视化调试**: 一套 Annotators 搞定所有调试输出

MVP阶段可以先不引入, 进入 **Phase 2 (移动化/AI眼镜)** 时整合 Supervision, 替代光流追踪方案。
