# VPS配置评估与产品推荐

> 日期: 2026-05-22 | 基于: 实际资源测算 + 各厂商现行定价
> 用途: 支持云端基础设施层 (RMQTT + BoardService + MariaDB + PluginManager)

---

## 1. 资源需求测算

### 云端运行的所有组件

| 组件 | 类型 | 估算内存 | CPU需求 | 存储 |
|:-----|:-----|:--------|:--------|:-----|
| RMQTT Broker | Erlang OTP | 50-150MB | 1核 ~5% | ~50MB |
| BoardService | Python 3.11 | 100-300MB | 1核 ~10% | ~50MB |
| MariaDB | MySQL兼容 | 300-800MB | 1核 ~15% | ~5-20GB (数据增长) |
| Nginx | 反向代理 | 20-50MB | 1核 ~2% | ~20MB |
| Plugin系统 | BoardService内 | 已计入BoardService | 同BS | 同BS |
| Supervisor (可选) | Python | ~50MB | 1核 ~5% | ~10MB |
| Ubuntu OS | Linux | 200-400MB | - | ~10GB |
| **合计** | | **~1-2GB** | **2核足够** | **~15-30GB** |

### 关键结论

> 在10个Agent并发、每小时~6000条消息的典型负载下：
> - **2核 / 4GB RAM / 40GB SSD** 是推荐的起点配置
> - **1核 / 2GB** 能跑但余量小 (仅适合验证阶段)
> - **4核 / 8GB** 是奢侈配置，除非有大量HTTP REST查询

### 瓶颈分析

```
CPU:  ⬜⬜⬜⬜⬜⬜⬜⬜⬜⬜  剩余 ~70% (2核下)
内存: ⬜⬜⬜⬜⬜⬜⬜⬜⬜⬜  剩余 ~2GB (4GB下)
磁盘: ⬜⬜⬜⬜⬜⬜⬜⬜⬜⬜  可用 ~30GB (40GB下, 纯文本数据增长极慢)
带宽: ⬜⬜⬜⬜⬜⬜⬜⬜⬜⬜  MQTT消息极小, 余量充足
```

MariaDB 是唯一需要关注内存的组件: 设 `innodb_buffer_pool_size=512M` 即可控制在1GB以内。

## 3. 网络端口规划

云端VPS需要开放的端口:

| 端口 | 协议 | 用途 | 认证 | 是否公开 |
|:-----|:-----|:-----|:-----|:--------|
| **8883** | MQTTS | 全Agent MQTT连接 | TLS + JWT | 是 (所有Agent) |
| 443 | HTTPS | REST查询API | TLS + API Key | 是 (Admin/Operator) |
| 22 | SSH | 运维管理 | SSH Key | 是 (管理员, 禁用密码) |
| 3306 | MySQL | DB直连(可选) | 密码 | 否 (仅VPS内部) |
| 1883 | MQTT | 明文(可选, 内网) | - | 否 |

## 4. 最终推荐方案

### 方案A: 验证原型 (最低成本)

```
厂商: Vultr (东京节点) 或 阿里云(香港)
配置: 2核 / 2GB RAM / 40GB SSD
价格: ~¥45-86/月
用途: 测试连接、单Agent验证、好奇心讨论
限制: 无法运行大量查询, 但MQTT消息处理无压力
```

### 方案B: 正式运行 (推荐)

```
厂商: 阿里云 / 腾讯云轻量
配置: 2核 / 4GB RAM / 60GB SSD  
价格: ~¥65-70/月
用途: 多Agent生产运行
Buffer: 内存余量~2GB, 可支撑20+Agent并发
```

### 方案C: 大负载

```
厂商: 阿里云 / 腾讯云
配置: 4核 / 8GB RAM / 80GB SSD
价格: ~¥120-130/月
用途: 大量HTTP REST查询、大型讨论板
```

## 5. Docker Compose 资源分配参考

```yaml
# 部署时的docker-compose资源配置建议
services:
  rmqtt:
    mem_limit: 256m
    cpus: 0.5
    
  board_service:
    mem_limit: 512m
    cpus: 0.5
    
  mariadb:
    mem_limit: 1g     # 最大1GB
    cpus: 0.5
    environment:
      - MYSQL_INNODB_BUFFER_POOL_SIZE=512M  # 限制buffer pool
    
  nginx:
    mem_limit: 128m
    cpus: 0.1
```

4GB方案下 `board_service + mariadb + rmqtt + nginx + OS` 约占用 2-2.5GB, **余量1.5-2GB** 用于峰值和突发。

## 6. 带宽估计

MQTT消息量估算 (10个Agent, 每轮平均5条消息, 每30秒一轮):

```
每秒:   10 * 5 / 30 ≈ 1.7 条消息
每条:  ~1KB
日:     1.7 * 86400 * 1KB ≈ 147 MB/天
月:     ~4.5 GB/月
```

加上HTTP REST查询, 每月总流量 < 10GB。
**所有厂商的入门套餐(1TB/月)都绰绰有余。**
