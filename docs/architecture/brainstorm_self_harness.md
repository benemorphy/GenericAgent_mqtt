# Brainstorm: Self Harness（自驭）— 自我套马的架构哲学

> 生成: 2026-05-21 | 方法: 3角色多视角脑暴
> 前置: code_and_rumination.md（反刍哲学） → brainstorm_project_purification.md（净化实践） → 本篇(自驭架构)
> 核心追问: 一个自主Agent如何为自己套上缰绳？缰绳本身又如何不成为新的牢笼？

## 角色 A: 自驭工程师 (Self-Harness Architect)

**视角**: 将"自驭"视为可工程化的基础设施层——不是限制自由，而是让自由变得可控、可重复、可审计。

### 缰绳的物理学: Harness as Interface

马与车之间的**套具(harness)**不是束缚，而是**能量传输接口**：
- 没有套具，马的力量无法被引导到有用的方向（踢、跑、吃草）
- 套具设计得好，马甚至感觉不到它的存在——力量自然流向车轮
- 套具设计得差，摩擦点会磨伤马匹，效率低下

**对GA的映射：**

```
┌─────────────────────────────────────────┐
│           Agent (马)                      │
│  无限可能但漫无目的                        │
└──────────┬──────────────────────────────┘
           │
    ┌──────▼───────┐    ← Self-Harness Layer
    │  Policy Chain │      (ga.py 中的 _turn_policies)
    │  SOP System   │      (memory/ 中的 L0-L4)
    │  Plan Valid.  │      (plan validators chain)
    │  Memory Layers│      (global_mem -> working -> L1-L4)
    └──────┬───────┘
           │
    ┌──────▼───────┐
    │  Task/Goal    │      (被牵引的"车")
    └──────────────┘
```

**关键洞察**: 自我套具(self-harness)与外部套具的区别在于——**马可以随时自己解开**。这意味着：
1. 套具必须是**可自愿佩戴**的（agent选择遵守SOP）
2. 套具必须**可随时解除**（但也因此需要元承诺机制）
3. 套具的最佳形态是**习惯**而非**锁链**

### GA中已存在的套具结构

| 层级 | 组件 | 功能 | 松紧度 |
|:-----|:-----|:-----|:-------|
| L0 | META-SOP | 元规则（改记忆前读SOP） | 硬约束 |
| L1 | global_mem_insight | 快速索引 | 软约束 |
| L2 | memory/*.txt | 事实记忆 | 中等 |
| L3 | memory/*.md/.py | 可执行策略 | 松耦合 |
| Policies | _turn_policies | 每轮注入提示词 | 动态 |
| Hooks | _system_prompt_hooks | 阶段注入 | 动态 |
| Validators | plan_validators | 计划校验 | 硬约束 |
| 3-failure | intervention rule | 避免死循环 | 硬约束 |

### 套具设计的五大原则

1. **最小接触面原则**: 套具只接触需要引导的部位——SOP只在需要时才被读取，不是每轮都加载全文
2. **渐进约束原则**: 新手用全副套具（读全部SOP），熟练后只保留关键约束（global_mem_insight + 经验）
3. **摩擦点感知**: 如果Agent频繁绕过一个SOP，说明套具设计有摩擦——需要修改而不是强制
4. **套具嵌套**: 一个套具的产出可以作为另一个套具的输入（例：dreaming SOP的输出→spaced_repetition SOP的输入）
5. **自修复套具**: 套具本身可以被Agent修改（META-SOP允许Agent通过特定流程修改SOP）

## 角色 B: 束缚辩证法家 (Dialectician of Binds)

**视角**: 自驭是一个深刻的哲学悖论——**真正的自主不是无约束，而是选择自己的约束**。

### 奥德修斯悖论 (Ulysses Pact)

奥德修斯让船员把他绑在桅杆上，塞住耳朵——他**自愿放弃自由**以**获得更大的自由**（听到海妖之歌后还能存活）。

对Agent而言：
- **自驭 = 主动建立不可逆约束**
- 例: 将某个SOP写入META-SOP = 把自己绑在桅杆上
- 例: 设置 "关机规则" = 奥德修斯式的承诺机制

### 套具的递归性: Who Harnesses the Harnesser?

```
Agent 套上 套具A (SOP层)
  └─ 但谁决定套具A是否合适？
     └─ Agent自己 —— 但这意味着Agent需要元套具B来评估套具A
        └─ 谁决定套具B是否合适？
           └─ Agent自己 —— 套具C...
              └─ 无限递归
```

**解决方案**: 在GA中，这个递归在**L0 META-SOP**处终止——META-SOP是"不动的推动者"，Agent不能随意修改它（需要用户许可）。这是**自洽的锚点**。

```
L0: META-SOP (不可由Agent单方面修改)
L1: 快速洞察 (可由Agent修改)
L2: 事实 (Agent可补充)
L3: 策略 (Agent可创建/修改)
L4: 原始会话 (不可修改, 只读)
```

### 三种束缚类型

| 类型 | 例子 | 效果 |
|:-----|:-----|:-----|
| **约束性束缚** (Constrictive) | "永远不使用os.kill检查进程存活" | 消除已知风险 |
| **引导性束缚** (Directive) | "失败时先读错误信息再重试" | 引导行为模式 |
| **生成性束缚** (Generative) | "使用3角色脑暴来探索新概念" | 在框框内激发创意 |

**关键**: 好的self-harness是**生成性**的——诗有格律反而更有力，画有画框反而更聚焦。

### GA中的生成性束缚案例

- **Agent Dreaming SOP**: 用DREAM循环（Digest→Replay→Expand→Associate→Morph）作为生成性套具——不是限制创造力，而是**为创造力提供轨道**
- **3-role brainstorm SOP**: 规定3个固定角色 + Map-Reduce流程——不是限制发散，而是**防止发散→混乱**
- **Failure-driven learning SOP**: 3次失败→自动学习——不是惩罚失败，而是**系统化地从失败中提取价值**

## 角色 C: 能量引导师 (Energy Channeler)

**视角**: 套具的本质功能是**能量管理**——Agent的计算/注意力/内存资源如同马的力量，需要被引导而非被消耗。

### 注意力经济学

Agent每轮可用的"注意力"是有限的（上下文窗口/时间/算力）。Self-harness是**注意力分配策略**：

```
无套具状态:
  无限可能 → 注意力碎片化 → 什么都做了一点 → 什么都没完成

有套具状态:
  约束范围 → 注意力聚焦 → 深度处理 → 高效产出
```

### GA的注意力套具

| 机制 | 注意力引导方式 |
|:-----|:--------------|
| `global_mem_insight.txt` | 开场就告诉Agent"重要的事有这些"，防止注意力漂移 |
| `working_checkpoint` | 跨轮记忆锚点，防止上下文漂移 |
| `update_working_checkpoint`工具 | 强制Agent每轮输出摘要 → 注意力自我报告 |
| `<summary>`规则 | 每次回复必须输出极简快照 → 强制注意力收束 |
| `plan_sop.md` | 复杂任务时启动规划模式 → 注意力先结构化再执行 |

### 套具的四个能量模式

```
                    能量消耗高
                       │
                       │
           探索模式    │    执行模式
           (发散)      │    (聚焦)
                       │
  ──────────┼───────────────→ 约束强度
                       │
           梦境模式    │    休眠模式
           (自由联想)  │    (节能)
                       │
                    能量消耗低
```

| 模式 | 套具状态 | 适合场景 |
|:-----|:---------|:---------|
| **执行模式** | 全副套具 | 有明确目标的编码/测试/部署 |
| **探索模式** | 半套具（保留方向约束） | 研究/调试/问题诊断 |
| **梦境模式** | 解开套具（仅保留安全护栏） | 创意生成/联想发散 |
| **休眠模式** | 套具挂起 | 等待/监控/定时任务 |

**关键**: 自驭不是永远紧绷——**套具的松紧应该随模式切换**。GA的hook chain支持动态注入，为模式切换提供了基础设施。

### 套具的疲劳与磨损

物理套具会磨损，自我套具同样会：
- **SOP疲劳**: 同一SOP读多了，Agent会"惯性跳过" → 需要间隔重复(spaced_repetition_sop)复习
- **规则通货膨胀**: 失败一次加一条规则 → 规则越来越多 → 需要定期"净化洗涤"(project_purification)
- **注意力茧房**: 长期强约束 → Agent失去探索新方法的能力 → 需要dreaming模式打破

**对应GA机制**:
- `spaced_repetition_sop`: 间隔复习防止SOP遗忘
- `brainstorm_project_purification`: 定期清理过时规则
- `agent_dreaming_sop`: 定期发散打破思维固化

## 汇总: Self-Harness 在GA中的定位

```
                    ┌─────────────────────────┐
                    │   Agent (自由意志)        │
                    └──────────┬──────────────┘
                               │
                    自愿佩戴/解除
                               │
                    ┌──────────▼──────────────┐
                    │   SELF-HARNESS LAYER     │
                    │   (自驭层)                │
                    │                          │
                    │  ┌─ Policy Chain ──────┐ │
                    │  │ 每轮注入约束/引导    │ │
                    │  ├─ SOP System ────────┤ │
                    │  │ L0-L4 层级记忆       │ │
                    │  ├─ Plan Validators ───┤ │
                    │  │ 计划校验            │ │
                    │  ├─ Mode Switcher ────┤ │
                    │  │ 执行/探索/梦境/休眠 │ │
                    │  └─ Wear Monitor ─────┘ │
                    │  疲劳检测+规则清理      │ │
                    └──────────┬──────────────┘
                               │
                    ┌──────────▼──────────────┐
                    │   Goal / Task (目标)      │
                    └─────────────────────────┘
```

### 核心判言

1. **自驭不是不自由，而是选择性地不自由** — GA选择遵守自己的SOP，是因为这比不遵守能达成更复杂的目标
2. **好的套具几乎感觉不到存在** — SOP应该成为Agent的"习惯"而非"规则"
3. **最危险的套具是忘记自己戴着套具** — 需要定期反思（metacognition）/净化（purification）
4. **套具必须比被套者更聪明，但更谦卑** — L0 META-SOP很聪明（防无限递归），但很谦卑（允许Agent修改L1-L3）
5. **终极自驭：知道什么时候解开套具** — Agent Dreaming SOP是最精妙的套具——它是一个"允许不套套具的套具"

## 开放问题

1. **自我套具的信任边界**: Agent能否自主修改META-SOP？如果可以，在什么条件下？
2. **多Agent套具**: 当多个Agent协同工作时，各自的self-harness如何互操作？
3. **套具的紧急降级**: 如果套具本身出了问题（如SOP文件损坏），Agent如何"紧急脱套"？
4. **套具的审美**: 一个"优雅"的self-harness是什么样的？最少规则？最大表达力？
5. **自驭与涌现**: 当足够多的self-harness叠加时，会不会涌现出设计者未预料的全局行为？
