## 核心命题

**本体模型应当用什么形式表示？** 图、向量、概率、函数——它们如何统一？

> 第一轮问的是"循环怎么做"（过程），这一轮问"被修的东西到底是什么"（结构）。

## Phase 2: 发散 — 5个Agent视角

---

### Agent 1: 知识工程师（符号派）

**核心主张：本体必须是形式化的符号系统**

#### 为什么符号不可替代

向量嵌入擅长"相似度匹配"，但无法处理：
- **传递推理**：A→B→C 推导出 A→C
- **约束满足**：必须在时间T前完成，且资源R不超过X
- **反事实推理**：如果没有发生E，会怎样？
- **解释生成**：为什么得出结论C？因为E1, E2, E3

这些都需要**符号图**。

#### Neo4j 作为符号层的天然选择

```
(n:Service {name:"gateway", port:8000})
-[:DEPENDS_ON]->(m:Service {name:"md_server_rs", port:8899})
-[:LISTENS_ON]->(h:Host {ip:"127.0.0.1"})
```

- 查询语言（Cypher）本身就是推理语言
- 图遍历 = 链路追踪（排查502时使用的正是这个思维模型）
- 路径模式匹配 = 差异检测

#### 符号层的局限

- 概念边界僵硬（要么是A要么不是A）
- 无法表达不确定性（连接可靠程度95% vs 99%）
- 无法自动演化（需要人来添加/修改模式）

#### 核心主张：符号层是本体模型的"宪法"

不是所有知识都需要符号化——但**元知识**（关于知识的知识）必须符号化：
- 本体的**结构骨架**（类层次、主要关系类型）
- **推理规则**（如果X则Y）
- **约束条件**（实体必须满足的规范）
- **版本差异**（rev1和rev2之间增删了什么）

**存什么**：骨架、规则、约束、版本差异
**不存什么**：具体的实例细节、模糊的相似关系、时序变化模式

### Agent 2: 表征学习专家（向量派）

**核心主张：世界是连续的，本体必须是连续的**

符号图是**离散的**，但Agent感知的世界是**连续的**。离散化必然丢失信息。

#### 向量嵌入解决的三个问题

1. **渐变**：猫→老虎不是离散跳变，而是连续渐变——向量空间里它们沿"体型"维度逐渐拉开
2. **类比**："国王之于王后，如同丈夫之于妻子"——向量运算 king - man + woman ≈ queen
3. **模糊匹配**：用户说"启动那个文档服务"——向量检索能匹配到"md_server_rs"，尽管文本完全不同

#### 本体向量化的层级

| 层级 | 粒度 | 用途 |
|------|------|------|
| 概念嵌入 | 类/概念的语义向量 | 跨本体映射、类比推理 |
| 实体嵌入 | 具体实例的向量 | 相似实体检索、异常检测 |
| 关系嵌入 | 关系的语义向量 | 关系类型推断 |
| 上下文本体 | 当前任务上下文的向量 | 注意力聚焦 |

#### 向量本体的本质 = 几何流形

"本体进化"本质上是**向量空间中的轨迹跟踪**——新数据到来时，嵌入空间发生形变（类似地球板块漂移）：
- **实体漂移**：一个概念随着新数据改变含义
- **维度涌现**：随着知识积累，新的语义维度自然浮现
- **聚类重组**：概念聚类边界随数据变化

#### 向量层的致命缺陷

- **无法精确推理**：不能做传递闭包
- **缺乏可解释性**："因为它离这个向量近"不是好解释
- **灾难性遗忘**：增量学习时新数据冲掉旧知识

#### 核心主张：向量层是本体模型的"土壤"

符号层生长在向量层之上。向量层提供"语义空间"——它告诉符号层：**哪些东西可能相关**（缩小搜索范围），但最终推理由符号层完成。

### Agent 3: 概率图模型专家（贝叶斯派）

**核心主张：世界充满不确定性，本体必须表达置信度**

符号派说"服务A依赖服务B"，向量派说"服务A和服务B语义相似"——但真实世界的问题是："服务A依赖服务B的概率是87%"。

#### 本体模型的核心问题是不确定性管理

排查502时真正的问题是：
- md_server_rs 应该在8899吗？**可能是**（配置写死了8899）
- 但它实际在8889吗？**确认是**（netstat验证）
- "应该"和"实际"之间的差异，就是推理的不确定性

概率本体模型的基本单元：
```
P(Service_A.depends_on(Service_B)) = 0.87
P(Service_B.port == 8899 | observed_port == 8889) = 0.95
```

#### 本体推理 = 贝叶斯更新

每轮感知-预测-修正循环，本质上是**贝叶斯更新**：
- 先验 P(Model) = 当前本体模型的置信度
- 似然 P(Perception|Model) = 模型对感知的预测能力
- 后验 P(Model|Perception) ∝ P(Perception|Model) × P(Model)

**关键推论**：Agent不应该"相信"一个单一的本体，而应该维护**本体分布**——多个可能的候选本体，每个有置信度权重。

#### 概率层的工程实现

```
# 在Neo4j中给关系加权重
(a)-[:DEPENDS_ON {confidence: 0.87, observed: 3, updated: "2026-05-31"}]->(b)
```

- 每条关系和属性都有置信度
- 置信度随着观测次数增加而更新
- 低置信度关系触发主动验证（发送探测请求）
- 高置信度关系减少验证频率

#### 收敛的贝叶斯解释

收敛不是"模型完全正确"——而是**后验分布不再随新数据显著变化**（不再有信息增益）。这时Agent可以释放认知资源。

#### 核心主张：概率层是本体模型的"新陈代谢"

置信度标注使本体从"死数据"变成"活系统"——它告诉Agent：
- **什么需要验证**（低置信度）
- **什么可以直接用**（高置信度）
- **什么已经过时**（置信度随时间衰减）

### Agent 4: 函数式/组合子派（计算本体论）

**核心主张：本体不是数据库，而是可组合的算子集**

前面三个Agent都隐含一个假设——本体是"存储知识的容器"。换个角度：**本体是"产生预测的函数集合"**。

#### 本体 = 函数

```
predict(本体, 当前状态) → 期望感知
explain(本体, 感知差异) → 模型修正
compose(本体A, 本体B) → 融合本体
```

每个"概念"不是一个存储块，而是一个**计算过程**：
- "服务"概念 = 能回答"这个进程有没有监听端口？"的函数
- "依赖"关系 = 能回答"如果A挂了，B会受影响吗？"的函数
- "收敛"状态 = 能输出"当前模型还有多少不确定性"的函数

#### 组合性

本体的真正力量不在于它"包含了多少实体"，而在于**实体可以组合出新的预测能力**。

```
md_server_rs + gateway + JWT = "文档服务需要先登录"
```

如果不组合，这些实体各自只能回答孤立问题。组合后能回答**涌现问题**。

#### 本体的"类型系统"

每个实体和关系都有**类型签名**（类似函数签名）：
```
Service: (host, port) → {running: bool, latency_ms: int}
Dependency: (Service, Service) → {failure_prob: float}
Prediction: (Model, State) → Perception
```

这使本体模型可以：
- **类型检查**：这个实体能用在这些推理中吗？
- **自动补全**：缺少什么信息才能回答这个问题？
- **抽象**：高层次"概念"由低层次"概念"组合而成

#### 核心主张：本体 = 可组合的预测算子图

不是"存了什么"，而是**能算什么**。最好的表示就是执行本身——本体模型就是一段可执行的预测程序。

### Agent 5: 系统观察者（元视角）

**核心主张：你们都对了——本体必须是多层的**

四个Agent各自抓住了本体模型的一个维度：

| 层 | 比喻 | 负责 | 技术实现 | 无法单独解决的问题 |
|----|------|------|---------|------------------|
| **符号层** | 宪法 | 精确推理、约束、解释 | Neo4j/Cypher | 模糊匹配、渐变概念 |
| **向量层** | 土壤 | 相似度、类比、模糊检索 | 嵌入模型 | 精确推理、解释生成 |
| **概率层** | 新陈代谢 | 不确定性、置信度、更新 | 置信度标注 | 组合推理、涌现 |
| **计算层** | 肌肉 | 可执行预测、组合性 | 函数/算子 | 存储、演化 |

**单一表示都不够——需要协同工作。**

#### 四层协作的典型场景

**场景：Agent被问到"文档服务为什么504？"**

```
1. 向量层：将"文档服务"映射到最接近的实体 → md_server_rs (score 0.94)
2. 符号层：查询 md_server_rs 的依赖图 → gateway → JWT → 用户登录状态
3. 概率层：P(未登录导致504) = 0.87, P(端口不通) = 0.65
4. 计算层：组合 (gateway_proxy(port=8899) + md_server_rs(port=8889)) = 端口不匹配
```

四层联合推理，比任何单层都强。

#### 层间通信协议

不需要统一的表示——只需要统一的**接口契约**：

```
向量层 → 符号层: "md_server_rs 可能是你要找的实体，置信度0.94"
符号层 → 概率层: "我找到了md_server_rs和gateway之间的relation，给它一个置信度"
概率层 → 计算层: "这个推理链的总体置信度是0.87，路径长度3跳"
计算层 → 符号层: "组合推理结果：端口不匹配是根因"
```

#### 本体模型的"生命史"

```
第1天:  向量层先启动（零样本嵌入，不需要预先定义模式）
第3天:  符号层从向量层聚类结果中提取模式（自动创建概念/关系类型）
第7天:  概率层基于符号层的推理成功/失败历史标注置信度
第14天: 计算层从频繁使用的推理路径中提取可组合算子
```

本体模型不是被"设计"出来的——它是从模糊的感知中**自组织**出来的。

#### 收敛的层次含义

| 层 | 收敛含义 |
|----|---------|
| 向量 | 实体嵌入不再显著移动 |
| 符号 | 图结构趋于稳定，新增/修改减少 |
| 概率 | 置信度不再显著变化 |
| 计算 | 组合算子集稳定，不再需要新算子 |

只有当**所有四层都收敛**时，才进入"创造模式"。

## Phase 3: 收敛 — 四层一体的本体模型架构

### 架构总图

```
┌──────────────────────────────────────────────────┐
│                 计算层 (算子/函数)                  │
│  可组合预测引擎、推理链模板、场景模拟器             │
├──────────────────────────────────────────────────┤
│                 概率层 (置信度)                    │
│  贝叶斯更新、不确定性标定、主动验证调度             │
├──────────────────────────────────────────────────┤
│                 符号层 (图/规则)                    │
│  Neo4j 概念/关系/约束、Cypher推理、规则引擎        │
├──────────────────────────────────────────────────┤
│                 向量层 (嵌入)                      │
│  概念嵌入、实体嵌入、上下文本体、相似度检索         │
├──────────────────────────────────────────────────┤
│               原始感知 (传感器/工具)               │
└──────────────────────────────────────────────────┘
```

### 各层的GA项目实现

| 层 | 现成组件 | 需新增 |
|----|---------|-------|
| 向量层 | LLM嵌入 + 向量索引 | 嵌入存储/更新机制 |
| 符号层 | Neo4j + Cypher | 自动模式提取 |
| 概率层 | — | 置信度标注+贝叶斯更新 |
| 计算层 | ga.py + tools/ | 算子注册/组合/评估 |

### 三层本体（Three-Body Ontology）

基于此架构的本体论宣言：

- **第一本体（先天本体）**：向量层，Agent生来就有的语义空间
- **第二本体（后天本体）**：符号层，从经验中提取的结构化知识
- **第三本体（元本体）**：概率+计算层，关于如何使用本体的本体

## Phase 4: 建议

### 建议1（短期可做）：Neo4j + 置信度标注

现在就在Neo4j中添加置信度属性和版本追踪：

```cypher
MATCH (a:Service {name:"gateway"})-[r:DEPENDS_ON]->(b:Service {name:"md_server_rs"})
SET r.confidence = 0.7, r.observed_count = 3, r.last_updated = datetime()
```

这不需要新架构，只是使用方式的改变。

### 建议2（中期）：向量-符号双检索

感知输入时的处理流程：
1. 向量检索找到 Top-K 候选实体
2. 符号推理在候选实体间做精确查询
3. 组合输出预测

```
用户输入 → [向量层: 模糊匹配] → [符号层: 精确推理] → 预测输出
                ↓                      ↑
          候选实体列表 ←—— 缩小搜索范围 ——
```

### 建议3（长期）：四层自组织

构建一个**本体模型的自组织管道**：
1. 原始感知 → 向量层（嵌入存储）
2. 向量聚类 → 符号层（自动提取概念类别）
3. 符号推理成功/失败 → 概率层（标注置信度）
4. 高频路径 → 计算层（固化算子组合子）

不需要人工设计本体——让本体从交互中**生长**出来。

## 总结

```
本体模型不是一种数据结构——它是四层协同的生态系统:

  向量层: 连续语义空间  (土壤 — 什么可能存在)
  符号层: 离散概念结构  (宪法 — 什么是确定的)
  概率层: 置信度与更新  (新陈代谢 — 该信多少)
  计算层: 可组合预测器  (肌肉 — 能算什么)

  四层合一 → 本体模型 = 活的预测系统
  而非     → 本体模型 = 死的知识仓库
```
