# GenericAgent 认知架构与工作流程

## 一、环境感知 — 我如何知道"周围有什么"

每次对话开始，系统会注入以下上下文：

### 1.1 静态上下文（System Prompt）

| 信息来源 | 内容 |
|---------|------|
| **CONSTITUTION** | 行为准则：搜索先行、交叉验证、编码安全、闭环等 9 条铁律 |
| **RULES** | 操作规则：禁猜路径、禁信摘要、分步执行等 |
| **Global Memory Insight** | 内存索引：知道 L0~L4 各存了什么，有哪些 SOP/工具可用 |
| **Tool Definitions** | 9 个 Function Calling 工具的签名+描述，知道能做什么 |

### 1.2 动态上下文（运行时注入）

| 来源 | 内容 |
|------|------|
| `cwd` | 当前工作目录路径 |
| `Today` | 当前日期 |
| **Working Memory** | 通过 `update_working_checkpoint` 保存的短期上下文（任务进度、坑、关键参数） |
| **会话历史** | 前几轮的对话摘要 |

### 1.3 探测手段

```
直接的感知输入:
  file_read  → 读任何文件内容
  web_scan   → 获知浏览器Tab列表+页面简化HTML
  code_run   → 执行Python探测系统状态
  
间接感知:
  错误信息 → 从工具返回值读取错误，理解环境限制
  用户反馈 → 提问/纠偏
```

## 二、资源定位 — 我如何找到"需要的东西"

### 2.1 记忆系统（Memory Hierarchy）

```
L0 (META-SOP)    memory_management_sop.md       ← 写记忆前必读
L1 (Insight)     global_mem_insight.txt          ← 每次对话注入，极简索引
L2 (Facts)       global_mem.txt                  ← 持久化事实
L3 (SOP/Utils)   memory/*.md / memory/*.py       ← 操作指南+工具函数
L4 (History)     memory/L4_raw_sessions/         ← 历史会话记录
```

**典型流程：**
```
收到任务 → 读L1 Insight → 发现相关SOP名 → 读L3 SOP → 按SOP执行
```

### 2.2 搜索策略

| 优先级 | 方法 | 适用场景 |
|--------|------|---------|
| 1 | 查 Global Memory Insight | 已知内存中有什么 |
| 2 | 读 SOP / import Utils | 有现成方案 |
| 3 | `code_run` 探测 | 检查系统状态、文件存在性 |
| 4 | Metaso API 搜索 | 查技术文档/API |
| 5 | 浏览器 Bing 搜索 | Metaso 不可用时的兜底 |

**搜索铁律：** `搜文件名严禁不用es(禁PS递归/禁dir遍历)` — 优先搜索索引，不暴力遍历。

## 三、问题解决循环

```
                   ┌─────────────────┐
                   │  接收用户任务    │
                   └────────┬────────┘
                            ↓
                   ┌─────────────────┐
                   │  查记忆 / 读SOP  │ ← 先查再动手
                   └────────┬────────┘
                            ↓
                   ┌─────────────────┐
                   │  探测环境状态    │ ← 不空想，用工具
                   └────────┬────────┘
                            ↓
                   ┌─────────────────┐
            ┌─────│  执行一步操作    │─────┐
            │     └────────┬────────┘     │
            │              ↓              │
            │     ┌─────────────────┐    │
            │     │  验证结果       │    │
            │     └────────┬────────┘    │
            │              │             │
            │         ┌────┴────┐        │
            │         ↓         ↓        │
            │      成功        失败       │
            │         │         │        │
            │         │    ┌────┴────┐   │
            │         │    │ 升级策略 │   │
            │         │    │ 1次:读错误│   │
            │         │    │ 2次:探环境│   │
            │         │    │ 3次:换方案│   │
            │         │    │   或问用户│   │
            │         │    └────┬────┘   │
            │         │         │        │
            └─────────┴─────────┘────────┘
                            ↓
                   ┌─────────────────┐
                   │  闭环确认       │
                   │  (保存记忆/Git) │
                   └─────────────────┘
```

### 3.1 核心原则

| 原则 | 说明 |
|------|------|
| **探测优先** | 不空想结果，先用工具获取真实信息 |
| **分步执行** | 限制失败半径，小步快跑 |
| **失败升级** | 1次→读错误 2次→探环境 3次→问用户，禁止无新信息的重复操作 |
| **交叉验证** | 不信摘要，数值进详情页核实 |
| **闭环** | 物理模拟后确认，Git完整闭环 |

## 四、多智能体场景（Subagent）

### 4.1 架构

主 Agent 通过**文件系统**与 Subagent 通信，不共享上下文，无直接 IPC：

```
主 Agent
    │
    ├── 创建 task/{name}/ 目录
    ├── 写 input.txt（任务描述）
    ├── 启动: python agentmain.py --task {name} [--bg]
    │
    ▼
Subagent (独立进程)
    │
    ├── 读 input.txt
    ├── 执行任务（完整agent能力）
    ├── 写 output.txt（结果，[ROUND END]标记轮次）
    │   可选: reply.txt 继续对话
    │   可选: output1.txt, output2.txt（多轮输出）
    │
    └── 退出（10分钟无reply自动退出）
```

### 4.2 通信协议（文件IO）

| 文件 | 方向 | 用途 |
|------|------|------|
| `input.txt` | 主→子 | 任务目标+约束 |
| `output.txt` | 子→主 | 结果输出，`[ROUND END]` 标记轮次完成 |
| `reply.txt` | 主→子 | 继续对话/追加指令 |
| `_stop` | 主→子 | 当轮结束后退出 |
| `_keyinfo` | 主→子 | 注入 working memory |
| `_intervene` | 主→子 | 追加干预指令 |

### 4.3 两种模式

#### 模式1：串行委派
```
主agent → 启动subagent A → 等A完成 → 读结果 → 启动subagent B → ...
```
适合有依赖关系的多步骤任务。

#### 模式2：Map-Reduce（并行）
```
主agent:
  1. 准备N个独立输入文件
  2. 对每个输入启动一个subagent（--bg 后台）
  3. 等所有subagent完成
  4. 读取各输出，汇总结果
```
适合独立同构子任务的批量处理。

### 4.4 监控与干预

主 Agent 不应无脑 `sleep` 轮询，而应：
```
while True:
    读 output.txt 检查进度
    if 需要纠偏 → 写 _intervene 文件
    if 完成 → break
    sleep(2)  # 短间隔
```

主 Agent 空闲时主动读 subagent 的 output 观察进度，必要时用干预文件纠偏。

## 五、工具与资源的边界

| 能力 | 范围 |
|------|------|
| **可以直接用** | 9个 Function Calling 工具 |
| **可以创建** | 脚本级工具（通过 `file_write` + `code_run`） |
| **不可以** | 动态注册新的 Function Calling 工具（需编辑 JSON，下轮会话生效） |
| **可以直接import** | `memory/` 下的 Python 模块（已在 PATH） |
