## 16:30 | 本次长会话经验教训总结

meta:
  type: daily_decision_log
  date: 2026-06-09
  topic: 经验总结
  tags: [lesson-learned, meta]
  status: completed
  upgrade: L3

### 结论
长达60+轮的会话（覆盖空目录清理/CodeGraph索引/项目整理/导入修复/gbrain SOP推送/L3.5落地），积累了6条关键教训。

### 关键教训

**1. 双CodeGraph数据库陷阱**
- 先后对同一项目跑了两遍codegraph init，Beneh根和GA下各有一个.codegraph/
- 索引分裂：主库315文件 vs 子库218文件，需要手动合并
- 教训：init前先检查是否有现成的.codegraph/

**2. .gitignore规则误伤**
- `config/` 规则 → 移动Docker文件到config/后被忽略
- `**log.*` 规则 → l35_log.py 被误匹配
- 教训：移动文件到新目录前，执行 `git check-ignore` 验证

**3. 过早下结论**
- 先断言 `Mqtt_bbs_server` 没有 `__init__.py` 是bug
- 实际文件存在，只是扫描范围没覆盖到Beneh根
- 教训：查代码问题先确认客观证据再下判断

**4. sophub API 调用流程清晰**
- keychain取key → API调用 → 异常处理
- 15分钟完成从认知到推送的完整闭环

**5. L3.5 学习→落地闭环高效**
- sophub下载SOP → 分析 → 制定方案 → goal mode执行 → 推送
- 外来知识内化的完整流水线：40分钟从学习到生产环境生效

**6. Goal Mode 适合多步骤任务**
- 7个milestone逐步推进，每步可验证、可恢复
- 比一次性脚本更可控

- 在global_mem.txt [RULES] 补充"git add前check-ignore"规则
