# parameter_fixation_sop — 参数固定策略: Fix One, Float the Rest
#
# 来源: knowledge-work-plugins/bio-research/scientific-problem-selection/04-parameter-strategy
# 适用: 复杂问题中决定哪些可变哪些固定, 避免"全部固定"的死锁
#
# 核心洞见: 大多数失败模式源于一开始固定了太多参数(系统+方法+应用)

## Step 1: 列出所有参数
# 从当前问题中提取所有可调参数, 例如:
#   系统/对象/目标 | 方法/工具/技术 | 应用/场景 | 环境/上下文 | 时间/节奏
#
# 列出时不判断重要度, 先穷举后筛选

## Step 2: 识别"神圣"参数
# 哪些参数是项目/问题的核心约束?
#   - 不能动的(客户需求/物理限制/安全约束)
#   - 可以讨论的(性能优化/实现方式/顺序)
#   - 完全自由的(辅助决策/边缘细节)

## Step 3: 应用Fix One, Float the Rest
# 从"神圣"参数中选择一个固定, 其他全部放开
# 检查:
#   [固定一个参数后, 其他参数的自由度是否产生新可能?]
#   [是否存在两个以上参数同时固定导致的死锁?]
#
# 示例: 空间转录组学肿瘤微环境研究
#   - 如果全部固定: 技术+细胞类型+环境 = 只有一条路
#   - 固定细胞类型(T细胞), 放开技术+环境
#     -> 可以用不同技术, 在不同肿瘤微环境中研究

## Step 4: 验证策略
# 对每个参数策略, 问三个问题:
#   1. 如果这个参数固定了——我还有什么选择?
#   2. 如果这个参数放开了——会有什么新可能?
#   3. 不同参数组合下, 产出质量差异多大?

## Step 5: 输出参数策略文档
# 格式:
#   - 固定参数: X
#   - 浮动参数: Y, Z, W
#   - 策略理由: ...
#   - 备选策略: 若固定Y浮动X会怎样?

## 何时使用
# [项目启动] - 定义核心策略时
# [卡住时]   - 尝试让一个"神圣"参数浮动
# [审查时]   - 检查是否有无意中固定了太多参数
