# First-Pass PRD 计划技能 SOP — Uber方法论适配

## 来源

Uber Engineering Blog: "Lessons from Building a First-Pass AI PRD Reviewer at Uber"
(https://www.uber.com/jp/en/blog/first-pass-prd/)

## 核心问题

项目的评审流程只有在**进入评审的材料质量足够高**时才有效。
问题不在于PM不严谨, 而在于**产品工作需要的360度视野在当下极难手动拼凑**:
相邻影响、跨部门依赖、历史实验、隐藏依赖、资深评审者会问的问题。

## 核心理念: 上游门禁

不是改变评审流程本身, 而是**提升进入评审流程的材料质量**。
AI PRD Evaluator 定位在审批系统上游, 在高成本评审发生之前强化材料。

## 4步方法

```
输入 [PRD草案] 
  ↓
Step 1: 构建全景知识库 [关联文档 + 历史实验 + 公司上下文]
  ↓
Step 2: 分类校准深度 [轻量/中量/全面/专项]
  ↓
Step 3: 多维度评估 [机会假设/范围/体验/指标]
  ↓
Step 4: 产出执行记分卡 [评级 + 维度评估 + 优先修复项]
  ↓
输出 [强化后的PRD + 行动清单]
```

### Step 1: 构建全景知识库

以PRD为入口, 用AI搜索关联的公司制品来拼出评估所需的上下文:

| 类型 | 来源 | 用途 |
|------|------|------|
| 关联文档 | PRD中链接的设计/技术/运营文档 | 校验假设一致性 |
| 历史实验 | 过去同类尝试的记录 | 避免重复造轮子 |
| 跨职能输入 | 法务/合规/科学团队前置意见 | 暴露盲点 |
| 公司上下文 | 核心原则/指标定义/关键任务 | 确保对齐 |

**适配到课件生成流程**:

```
P1模块输出 → 关联: P0本体概念 + P2模块映射 + 历史同类课件质量报告
             + 学科教学规范 + 年级认知水平标准
```

### Step 2: 分类校准深度

不是每个需求都需要同样深度的审查。按变更类型校准审查力度:

| 类型 | 示例 | 审查深度 |
|------|------|---------|
| 轻量 | UX完善/可发现性改进 | 格式+基本一致性 |
| 中量 | 增量工作流变更/内部工具迁移 | 逻辑+完整性+异常处理 |
| 全面 | 全新能力/平台特性 | 全维度深度审查 |
| 专项 | 策略定价/市场规则变更 | 全面+领域专项审查 |

**适配到课件审核门禁**:

```
学科类型 → calibration
  biology: 细胞图验证 + 生物概念深度审查 (全面)
  physics: LaTeX公式 + 物理仿真验证 (全面)
  math: Plotly图表 + 公式验证 (全面)
  chemistry: 分子结构SVG + 反应式验证 (全面)
  general: 轻量审查 (轻量)
```

### Step 3: 多维度评估

结构化评估维度 (每项给PASS/FAIL+依据):

| 维度 | 检查问题 |
|------|---------|
| 机会与假设 | 问题是否真实? 成功标准是否清晰可衡量? |
| 范围与边界 | 提案是否可理解? 范围是否合理? 决策是否就绪? |
| 用户体验与影响 | 是否覆盖不同用户群体/地域/边界情况? |
| 指标与数据严谨性 | 是否定义成功指标/护栏/可信验证方法? |

**适配到课件审核**:

| 课件维度 | 检查问题 |
|---------|---------|
| ABT叙事年级适配 | 叙事方式和深度是否匹配目标年级认知水平? |
| 矛盾转折点(BUT) | 转折点是否表达清晰, 让学生感受到问题所在? |
| 学员思考空间 | 是否留有自主思考和发现矛盾点的空间? |
| 知识关系深度 | 概念关系是否准确, 深度是否符合课标要求? |
| PBL拆解 | 项目式学习的问题拆解是否合理, 各环节是否到位? |
| LaTeX公式 | 科学公式是否正确使用LaTeX格式? |
| 图示完整性 | 是否使用mermaid/plotly/SVG可视化表达? |

### Step 4: 产出执行记分卡

不只是一堆评论批注, 而是结构化记分卡:

```
启动就绪评级:  [PASS / CONDITIONAL / FAIL]

维度评估:
  [PASS] ABT叙事年级适配: 使用初中生熟悉的日常场景引导, 认知负载适中
  [FAIL] 图示完整性: 概念流程图中有2个未转换的mermaid代码块
  [PASS] LaTeX公式: 正确使用 $$...$$ 格式, 无语法错误

最优先修复: 图示完整性 → 运行 _prerender_mermaid_in_html() 转换剩余代码块

关键要求:
  1. [高优] 转换剩余2个mermaid代码块为SVG
  2. [高优] 验证本体导航可点击跳转

优化建议:
  1. [中] 在模块3增加交互式拖拽练习
  2. [低] 增加更多PBL拆解步骤
```

记分卡设计原则:
- **不只是指出弱点**: 同时提供替换建议和证据引用
- **让下一轮修订更简单**: 给出write-ready的替换文本
- **让评审对话信号更强**: 关键问题已在记分卡中暴露

## 与GA auditor模块的整合

```python
from app.domain.courseware.auditor import audit_stage, Stage

# First-Pass PRD Style: 构建上下文知识库
context = {
    "grade": grade,           # 年级认知水平
    "subject": subject,       # 学科规范
    "prior_coursewares": [],  # 历史同类课件质量
}

# First-Pass PRD Style: 分类校准深度
depth = "full" if subject in ("biology","physics","math") else "light"

# First-Pass PRD Style: 多维度评估 + 记分卡
result = audit_stage(Stage.P0_PLAN, data, context, depth=depth)
print(f"评级: {result.rating}")         # PASS/CONDITIONAL/FAIL
print(f"最优先: {result.top_fix}")       # 最重要的修复项
print(f"关键要求: {result.critical}")    # 高优行动项
print(f"优化建议: {result.nice_to_have}") # 低优建议
```

## 关键启示

1. **上游介入**: 在问题进入高成本评审之前暴露, 而不是评审后补救
2. **360度视野**: 不是检查写法, 而是拼出决策所需的完整上下文
3. **行动导向**: 记分卡设计以让下一轮更容易为目标
4. **校准力度**: 不是一刀切, 按变更类型/学科调审查深度
5. **证据引用**: 每条评估都附带来源文档或实验数据, 而非凭空判断
