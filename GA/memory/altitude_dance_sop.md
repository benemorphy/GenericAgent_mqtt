# altitude_dance_sop — 高度舞蹈: 跨抽象层级切换
#
# 来源: knowledge-work-plugins/bio-research/scientific-problem-selection/05-decision-tree
# 适用: 卡在某个层级无法推进时, 主动切换上下层级
#
# 核心概念: 问题可以存在于不同抽象层级,
#   死磕一个层级往往无效, 层级切换本身可能就是突破

## 层级体系(从低到高)
# Level 0: 具体实现细节
#   - "这个API怎么调用?" / "这个SQL语法怎么写?"
#   - 特征: 操作层面, 具体技术
#
# Level 1: 方法选择
#   - "用什么工具/技术/算法?"
#   - 特征: 对比不同方法的优劣
#
# Level 2: 设计/实验方案
#   - "整体架构怎么设计?" / "实验怎么安排?"
#   - 特征: 流程/方案层面
#
# Level 3: 问题/目标
#   - "我们到底要解决什么问题?"
#   - 特征: 目标重新定义
#
# Level 4: 领域/方向
#   - "在这个方向上对不对?"
#   - 特征: 根本性审视

## 何时切换层级
# [卡住信号]:
#   - 在Level 0反复尝试无果 -> 升到Level 1问方法选择
#   - 在Level 1不知道选什么工具 -> 升到Level 2问方案设计
#   - 方案做得细但方向不对 -> 升到Level 3问目标本身
#   - 感觉整个领域走偏 -> 升到Level 4问方向

# [切换信号]:
#   - 在高层级太久(空谈不落地) -> 降到Level 0/1做具体
#   - 在低层级太久(只见树木不见林) -> 升到Level 2/3看全局

## 切换操作
# 上升: "等等, 我们退一步看看——我们到底在解决什么问题?"
# 下降: "好的, 那现在具体怎么做?" / "第一步是什么?"

## 示例
# 卡在Level 0: "这个SQL查询为什么慢?"
#    -> 升到Level 1: "是不是应该换种查询方法?"
#    -> 升到Level 2: "整体数据方案设计是否合理?"
#    -> 升到Level 3: "我们真的需要用这个查询吗? 目标是什么?"

## 注意
# 高度舞蹈的核心不是"哪个层级是对的"
# 而是"在不同层级间主动切换, 找到最有效的那个"
