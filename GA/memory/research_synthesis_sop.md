# research_synthesis_sop — 研究综合与主题分析
#
# 来源: knowledge-work-plugins/product-management/synthesize-research
# 适用: 散乱的研究笔记/调研资料/用户反馈需要提炼结构化洞见
#
# 核心方法: 主题分析(Thematic Analysis) 6步法
# 输出: 结构化研究综合报告

## 1. 收集输入
# 支持来源(任一):
#   [粘贴文本]: 访谈笔记/问卷回复/反馈记录
#   [上传文件]: 研究文档/电子表格/录音摘要
#   [知识库连接]: 搜索研究文档/访谈笔记/问卷结果
#   [用户反馈连接]: 拉取支持工单/功能请求/bug报告
#
# 先问用户:
#   - 研究类型? (访谈/问卷/可用性测试/分析/支持工单)
#   - 来源/参与者数量?
#   - 是否有特定假设或问题?
#   - 这些研究会支持什么决策?

## 2. 处理各来源
# 每份资料提取:
#   - 关键观察: 用户说了什么/做了什么/经历了什么
#   - 原话引用: 阐明要点的verbatim quotes(必须原文,不得意译)
#   - 行为: 用户实际做了什么(vs 他们说自己做了什么)
#   - 痛点: 挫折/变通方案/未满足需求
#   - 正面信号: 有效的/愉悦时刻
#   - 上下文: 用户细分/使用场景/经验水平

## 3. 主题分析6步法
# Step 1 熟悉化: 通读所有原始数据, 不急于编码
# Step 2 初始编码: 开放编码, 不预设类别
# Step 3 主题搜寻: 将编码归组为主题
# Step 4 主题评审: 检查主题内部一致性和外部区分度
# Step 5 主题定义: 命名 + 定义边界
# Step 6 撰写报告: 按优先级排列, 附引用证据

## 4. 优先级矩阵
# 按(频率 x 影响)分类:
#   [High频率+High影响] -> 最高优先级发现
#   [Low频率+High影响] -> 特定细分群体重要
#   [High频率+Low影响] -> 生活质量改进
#   [Low频率+Low影响] -> 记录但低优先
#
# 置信度标注:
#   High   = 强证据, 多源验证
#   Medium = 暗示性, 需进一步确认
#   Low    = 早期信号, 小样本

## 5. 输出结构
# === Research Overview ===
# - 方法论(研究类型/参与者数)
# - 研究问题(我们想了解什么)
# - 时间范围(何时进行)
#
# === Key Findings(5-8条, 每条含) ===
# - 发现陈述: 一句描述洞见
# - 证据: 援引引用/数据点/观察(标注来源)
# - 频率: 多少参与者/来源支持
# - 影响: 对用户体验或业务的影响程度
# - 置信度: High/Medium/Low
# 按优先级(频率x影响)排序
#
# === User Segments/Personas ===
# - 细分名称和描述
# - 关键特征和行为
# - 独特需求和痛点
#
# === Opportunity Areas ===
# - 未满足/未充分服务的用户需求
# - 当前方案不足处
# - 可解锁价值的新能力
# - 按潜在影响优先级排序
#
# === Recommendations ===
# 具体可操作建议:
# - 做什么/改什么/进一步研究
# - 回连到具体发现
# - 按影响和可行性排序
#
# === Open Questions ===
# - 研究未覆盖的空白
# - 需进一步研究的领域
# - 建议的后续研究方法

## 6. 错误处理
# [某数据源失败] -> 跳过并标注在Sources, 不阻塞
# [无数据] -> 记录为0并继续, 不警告
# [矛盾发现] -> 特别标注, 而非掩盖
